## 설계 요약

- 이미지 게시판을 새로 만든다. 요청서에 소스가 없는 신규 기능이므로 기존 샘플게시판(tbts_sample_board + SampleBoardController/Service/DAO/VO + sampleboard-mapper.xml + sampleBoard.jsp)을 참고 파일로 삼아 같은 구조로 만든다.
- 파일(이미지) 업로드는 프로젝트의 기존 첨부파일 모듈(tbsy_file_info + FileService#imageSave(UPLOADS.UPIMAGE))을 그대로 재사용한다. 신규 개발은 최소화한다.
- 상세화면은 팝업(.pop)으로 만들고 편집모드/조회모드 전환은 요청서 요구대로 지원한다. 저장 후 목록 갱신은 callbackFunc로 처리한다.
- 목록화면은 Kendo 그리드 + serverPaging 방식(pageable: true, BaseVO의 page/pageSize 사용)으로 구현한다.
- 목록에서의 썸네일은 tbsy_file_info.file_url 이미지를 축소 표시하고, 클릭 시 imageBoardImageViewPop.jsp에서 원본을 크게 보여준다(별도 썸네일 파일 생성은 하지 않음 - 결정 필요 사항 3번).

## 예외 처리 방침

- 제목 미입력: 화면에서 저장 전 차단(genexon.alert, 필수항목 표시).
- 이미지 파일이 아닌 파일 업로드: kendoUpload validation으로 이미지 확장자만 허용(요구사항 '확인 필요'의 업로드 제약 - 확정 전이라 일단 이미지 형식만 허용하는 최소한의 검증만 두고, 세부 제한은 결정 필요 사항).
- 삭제: use_yn='N' 처리(물리삭제 아님, 샘플게시판과 동일). 확인 다이얼로그는 confirm() 사용(요구사항 '확인 필요' 항목 - 임의 확정하지 않고 결정 필요 사항으로 남김).
- 조회모드에서는 저장/수정/업로드 버튼을 숨겨 읽기전용으로 만든다.

## TASK별 확인 방법

| TASK | 확인 방법 |
|------|-----------|
| TASK-01 | 테스트 > 이미지게시판 메뉴 진입 → 등록 버튼 클릭 → 상세팝업이 편집모드로 열림 → 등록자에 로그인 사용자명이 자동 세팅됨 → 제목 입력, 파일업로드버튼으로 로컬 이미지 선택 → 저장 클릭 → "정상처리되었습니다" 안내 후 팝업 닫힘 → 목록 재조회 시 게시물이 보임 → 목록에서 제목 클릭 → 상세팝업이 조회모드(읽기전용)로 열림 → 수정 후 저장 시 내용이 반영됨 |
| TASK-02 | 목록에서 썸네일 클릭 → 이미지 뷰어 팝업에 원본 이미지가 크게 표시됨 → 닫기 시 목록으로 복귀 |
| TASK-03 | 목록화면에 체크박스/SEQ/썸네일/제목/등록자 컬럼 표시 → 조회조건에 제목 입력 후 검색 시 제목에 포함된 건만 조회 → 페이징 동작 → 전체선택 클릭 시 전체 체크박스 체크 → 삭제 클릭 시 체크된 게시물이 목록에서 사라짐(use_yn='N') |

## 회귀 테스트 대상

- 테스트 > 샘플게시판(TS_100): 이번 변경으로 샘플게시판 소스/매퍼/테이블은 수정하지 않지만, 같은 패키지·같은 매퍼 폴더·같은 Controller URL 패턴을 공유하므로 목록/등록/수정/삭제가 기존과 같이 동작하는지 확인.
- 회원사관리(이미지 업로드 참고 기능): FileService#imageSave를 건드리지 않으므로 회사이미지 업로드가 기존과 같이 동작하는지 확인.
- 메뉴 표시: 실DB tbsy_resource의 TS_300 URL을 바꿀 경우 샘플게시판 메뉴 진입에 영향이 없는지 확인(TS_100은 그대로 유지).

## 결정 필요 사항

1. 메뉴 URL 변경: 실DB tbsy_resource TS_300 '이미지게시판'이 resource_url='/sample/board/sampleBoard.go'(샘플게시판)로 되어 있음. 이번 설계는 TS_300을 이미지게시판 전용 URL('/sample/board/imageBoard.go')로 쓰는 방향이며, 실DB UPDATE 문 실행 여부와 seed.sql 반영(#11)은 확정 필요. 대안: TS_300을 그대로 두고 새 TS_400 '이미지게시판'을 만든다 - 장점: 기존 메뉴 안 건드림 / 단점: '테스트' 메뉴에 샘플게시판이 두 개로 보일 수 있음.
2. 썸네일 생성 방식: 요구사항 '확인 필요' 항목. 이 설계는 "원본 file_url 이미지를 화면에서 축소 표시"로 갔다. 서버에서 별도 썸네일 파일을 만들려면 ImageUtil(kr.co.gnx.comm.util.ImageUtil) 활용 등 추가 개발이 필요 - 확정 필요.
3. 업로드 파일 제약: 허용 형식(jpg/png 등)과 최대 용량. 임의로 정하지 않고 확정 필요(현재 설계는 이미지 형식만 허용하는 최소 검증).
4. 권한/삭제 권한: 모든 사용자 등록·수정·삭제 허용 여부, 등록자만 삭제 가능 여부. 임의로 정하지 않고 확정 필요(현재 설계는 샘플게시판과 같이 로그인 사용자면 등록/수정/삭제 가능 + mb_id 단위로 데이터 분리).
5. 페이징 단위: 페이지당 건수(10/20건 등). 현재 설계는 그리드 기본값(pageable: true)을 따름 - 확정 필요.
6. 삭제 확인 다이얼로그: 필요 여부. 현재 설계는 confirm() 사용(사용자가 원치 않으면 제거).
7. FAQ(tbts_faq + 메뉴 TS_200만 있고 소스 없음): 본 요청과 무관하므로 손대지 않음.
