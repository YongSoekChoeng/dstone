프로젝트관리

작업 대상 프로젝트입니다. 소스 위치, 형상관리, WAS와 빌드, 프로젝트가 쓰는 DB(여러 개)를 적습니다. [Build]로 만든 리비전을 테스트 서버가 씁니다. DB는 Agent의 DB Tool이 프로젝트ID.DB이름 별칭으로 조회합니다. 계정은 읽기 권한만 있는 것을 쓰세요.

새로 만들기

git은 비밀번호 대신 액세스 토큰을 권장합니다. 암호화해 저장하고 다시 보여 주지 않습니다. 바꿀 때만 넣으세요.
(자동)이면 빌드 설정이나 클래스 파일에서 읽습니다. JDK 경로는 서버의 env 설정 JAVA_HOME_버전입니다.
WAS
테스트 서버는 원래 WAS를 Tomcat(Boot는 내장 서버)으로 바꿔 띄웁니다. EJB나 벤더 전용 기능을 쓰는 앱은 서버 기동 테스트를 하지 않습니다.
빌드 참고용 기본값입니다. 필요 없으면 지우고 저장하세요.
산출물 구조를 자동으로 못 찾을 때만 넣습니다(소스 루트 기준 상대경로).
저장한 설정으로 빌드합니다. 형상관리가 있으면 소스를 먼저 받습니다. 성공하면 그 리비전이 현재 리비전이 되고, 이미 시작한 실행은 시작할 때의 리비전을 계속 씁니다.
테스트 서버는 고객사 개발 DB에 붙으므로, 그 DB에 있는 테스트용 계정을 넣습니다. Agent가 화면에서 등록·수정·삭제를 해 보는 데 씁니다(테스트가 끝나면 데이터는 원복합니다).
암호화해 저장하고 다시 보여 주지 않습니다. Agent에게도 주지 않고, 엔진이 브라우저에 입력할 때만 넣습니다. 바꿀 때만 넣으세요.
여러 개는 줄바꿈으로 구분합니다(한 줄에 하나씩 '/주소=폴더'). 원래 서버에서 웹서버나 다른 설정이 열어 주는 주소를 적습니다. 예를 들어 앱이 웹앱 밖 폴더에 저장한 업로드 파일을 여는 주소입니다. Tomcat 테스트 서버가 그 주소를 그 폴더로 엽니다. 적지 않으면 테스트 서버에서는 그 주소가 404입니다.
테스트 서버에서 사람이 화면에 들어가는 순서를 적습니다. Agent가 테스트 서버를 띄울 때마다 이 글을 함께 받고 그대로 들어갑니다. 안쪽 화면의 주소를 바로 열면 동작하지 않는 앱은 꼭 적으세요.

비밀번호는 암호화해 저장하고 화면에 다시 보여 주지 않습니다. 고칠 때 비워 두면 저장된 비밀번호를 그대로 씁니다. JNDI 이름은 앱이 JNDI로 DB를 찾을 때(예: jdbc/myDS) 테스트 서버가 이 DB와 짝짓는 이름입니다.
