[1] 06-고객요청사항 분석 리뷰(step05)의 판정: 통과
사유:
요청서의 모든 요구(목록화면: 목록표시·페이징·테이블 항목·제목 조회조건, 기능버튼: 전체선택·등록·삭제, 이벤트: 제목 클릭 조회모드 팝업·썸네일 클릭 이미지 팝업, 상세화면: 제목·등록자 자동세팅·파일업로드버튼·로컬 이미지 선택·저장·수정, 메뉴위치 테스트>이미지게시판, 프로젝트ID·소스경로)가 TASK-01~04에 빠짐없이 반영되어 있고, 요청서에 없는 내용이나 뜻이 다른 내용은 없다. 완료 기준은 모두 '그렇다/아니다'로 확인할 수 있으며, 요청서만으로 알 수 없는 사항이 없어 확인 필요 사항이 없음으로 적힌 것도 적절하다. 4개 TASK 모두 통과로 판정하고 파일의 상태 칸을 반영했다.

[2] 10-영향도 분석 승인(step09)의 결정: 승인(설계진행) (승인자 admin)
의견:
A.. 메뉴와 테이블이 이미 DB에 존재한다(위 현행 확인). 소스에는 구현이 없어 신규 개발이 맞지만, 설계 시 다음을 그대로 따라야 하는지 확인 필요:
1. 메뉴 URL /sample/imageboard/imageBoard.go → 신규 화면·Controller 경로(패키지 kr.co.gnx.sample.imageboard, view /sample/imageboard/imageBoard)를 이 URL에 맞춰야 한다.
=> 이렇게 진행.
2. 테이블 tbts_image_board(컬럼 구성 위)를 그대로 사용해야 한다. 새 테이블을 만들지 않는다.
=> 새 테이블을 만들지 않음.
3. 대안: 메뉴·테이블을 무시하고 새로 만들 경우 DB 데이터(메뉴 1건)와 충돌하므로 비권장.
=> 새 테이블을 만들지 않음.
B. 삭제 방식: 샘플게시판은 실제 DELETE 대신 use_yn='N' 논리삭제다. 이미지게시판도 같은 방식인지, 파일(tbsy_file_info)까지 함께 삭제할지 설계 단계에서 정할 사항.
=> 논리삭제.
