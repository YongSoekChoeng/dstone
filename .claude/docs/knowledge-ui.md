Screens (M8, 2026-10-05; node map added 2026-10-06, next paragraph): this module has no UI; the screens live in **`dstone-boot`** (`webapp/WEB-INF/views/knowledge/**.jsp`, `webapp/knowledge/assets/{js,css}`, reached via `defaultLink.do?defaultLink=knowledge/dashboard/dashboard|knowledge/index|knowledge/search/search|knowledge/impact/impact|knowledge/diff/diff`, linked from `views/common/left.jsp` and the AI header). The browser never calls `dstone-knowledge` directly: `net.dstone.boot.knowledge.controller.KnowledgeProxyController` (`POST /knowledge/api/call.do` `{method, path, query, body}`) → `KnowledgeProxyService` forwards as is, restricted to paths under `/api/` (no `..`, `//`, `?`, `#`) and `GET`/`POST`/`DELETE`, and returns the upstream status + body untouched. It reports its own rejections as `{status, message}` `ResponseEntity`s instead of throwing, because `dstone-boot`'s global exception handling turns exceptions into HTTP 200 with a different body shape. Upload is separate (`/knowledge/api/upload.do`) and reads the file through `RequestUtil`, since `dstone-boot` runs with `spring.servlet.multipart.enabled=false` (a `MultipartFile` parameter is always empty there). Config: `interface.knowledge.base-url` (`KNOWLEDGE_HOST`/`KNOWLEDGE_PORT` in `dstone-boot/conf/env*.properties`; each profile loads exactly one env file, so a new variable must be added to all of them) and optional `interface.knowledge.api-key`.
