# dstone-ai-engine — 개요와 패키지별 설명

> CLAUDE.md에서 분리한 상세 메모입니다. 원문 그대로 옮겼으며, 필요한 작업일 때만 읽습니다.

### dstone-ai-engine: AI & MLOps Core Engine

A Spring AI-based, provider-agnostic engine meant to be reused across future SI projects. Fully redesigned on 2026-09-15 around a **Workflow → Step → Agent → Tool** model: Java (`runtime.workflow.WorkFlowExecutor`) controls the overall sequence/branch/parallel/loop shape, while the intelligent judgment inside each step (analysis, conversion strategy, tool choice) is left to the LLM. What a Workflow or Agent actually does is declared in definition files under `conf/definitions/` (outside the jar since 2026-10-20, location `dstone.ai.definition.location`, default `file:${APP_CONF_DIR}/definitions`) — `workflows/**/<id>.yml`, `agents/**/<id>.md` (one file per Agent: YAML front matter between `---` lines = settings + `input`/`output`, body = system prompt), `skills/**/<name>/SKILL.md`, `mcp/**/<id>.yml`, grouped into `pilot`/`sample`/`sm`/`testApp` folders — not in Java code or `application.yml`. There are no `prompts/` or `schemas/` folders and no top-level `workflow:`/`agent:`/`mcpServer:` wrapper since 2026-10-18 (the user's choice after asking for "the clearest, most intuitive in/out definition"); input/output shapes are written inline in **Picoschema**. **The definition format was replaced on 2026-10-09** following `docs/temp/dstone-workflow-design.md` (the user chose "the document's format in full" and "state-based data flow" over my recommendation to keep `steps.<id>.output` and a jq subset; LangGraph4j from that document was *not* adopted — the engine keeps its own state machine): **jq is gone** (no `jackson-jq` dependency), step results are stored by name into a shared `state`, and Workflow/Agent carry a required `version`. The 2026-10-18 change (one-file Agents, Picoschema, `with`/`save`/`return`, required `state:` declaration) is described below; older paragraphs were rewritten to it. Root package `net.dstone.ai`:

| `common.definition` | Pure records that mirror the definition files 1:1: `SchemaDefinition` (one contract = a standard JSON Schema map compiled from Picoschema by `common.schema.Picoschema`; a single DELEGATING creator takes the raw YAML value — a string like `string, 설명` or a field map) / `agent.AgentDefinition` (the Agent `.md` front matter: `id`, `version` (required), `role`, `description`, `model: {name, temperature, reasoning}`, `input` and `output` (Picoschema; `output` with fields = JSON + strict validation, absent or `string` = text — there is no `format`/`validation` key), `context: {sources: [workflowInput, retrievedDocuments], retrieval: {topK, similarityThreshold, allowEmptyContext}}`, `tools: {allowed: [...]}`, `subAgents`, `allowedCallers`, `execution: {maxAttempts, onInvalidOutput: RETRY\|FAIL, timeoutSeconds, maxToolCalls}`; `prompt` is a plain string = the file body, filled in by the loader and never written in the front matter — the blocks are nested records (`Model`/`Context`/`Retrieval`/`Tools`/`Execution`) and the rest of the engine reads them through derived accessors: `promptText()`, `modelName()`, `reasoningLevel()`, `temperature()`, `toolNames()`, `ragEnabled()` (= sources contains `retrievedDocuments`), `maxToolCalls()`, `maxAttempts()`, `timeoutSeconds()`, `declaresOutput()`, `inputSchema()`/`outputSchema()`) / `mcp.McpServerDefinition` / `workflow.WorkFlowDefinition` (`id`, `version` (required), `description`, `allowedCallers`, `input` (Picoschema), `settings: {checkpoint, maxIterations, onError}`, `state` = required map of every saved name → description (no types — they are inferred from the saving step), optional `return` (record field `returnValue`, `@JsonProperty("return")`; omitted = the whole state; there is no output schema check any more), `steps`) / `workflow.step` — one record per step type (`AgentStepDefinition`/`SupervisorStepDefinition`/`RouterStepDefinition`/`ToolStepDefinition`/`ApprovalStepDefinition`, chosen by YAML `type` via Jackson `@JsonSubTypes` on the sealed interface `StepDefinition`, which carries `id`/`type`/`onFailure`, a default `output()` that folds the `save…` keys into one `{result\|error\|input\|items → state name}` map for the executor and the registry, plus static `refOf`/`nextOf`/`routesOf`/`forEachOf`/`itemKeyOf`/`memoryOf` helpers). | `common.consts` | `Constants` (config-key/reserved-word constants, incl. the execution-context tree names under `Constants.WorkFlow.Context`: `input`/`state`/`approvals`/`definition`, the step-output source names `Constants.WorkFlow.Output`: `result`/`input`/`error`/`items`, the sentinels `END`/`FAIL` and the definition locations/suffixes under `Constants.Definition` — `workflows/` `.yml`/`agents/` `.md`/`mcp/` `.yml` (the folder decides the kind)) plus the enums `StepType` (`AGENT`/`SUPERVISOR`/`ROUTER`/`TOOL`/`APPROVAL`) and `McpTransport` (`STDIO`/`SSE`) |
| `common.expression` | `ContextResolver` (static, pure) — the only expression evaluator. **An expression is a path that reads a value, nothing more**: `${input…}`, `${state.name.field}`, `${state.list[0].x}`, `${item…}` (forEach variable), a default after a colon (`${state.a.comment:}`, `${input.mode:strict}`, nested `${state.fixed.sql:${input}}`). A whole-value expression keeps its JSON type; mixed into text it is interpolated (objects as JSON text, null as empty) and **the result is stripped of leading/trailing whitespace** (so `"${a:}\n${b:}"` is empty when both are missing). No operators, functions, filters or conditions — anything like that fails boot with "make it a Tool". Quotes are not needed in block YAML (`with: ${input}`); only a value with `\n` or one inside a one-line `{ }` map must be double-quoted (flow indicators) |
| `common.schema` | `Picoschema` — compiles the inline type notation to JSON Schema, following Google Dotprompt's Picoschema: `name: type, description` (types `string`/`number`/`integer`/`boolean`/`null`/`any`), `name?` optional **and nullable** (`type: [T, "null"]`, enum gets `null` too), `name(array, desc): itemType` or nested fields, `name(object, desc):` + fields, `name(enum, desc): [A, B]`, `(*): type` = `additionalProperties`. Two deliberate differences: field names may contain spaces/Korean/parentheses (only a trailing `(array\|object\|enum…)` group is a kind, e.g. `2. 현재 상태(As-Is)` is a plain name — testApp uses such names; a trailing lowercase word like `(string, …)` is an error with a hint), and undeclared fields are **not** rejected (no `additionalProperties: false`) because an LLM adding one field must not fail a step. `JsonSchemaUtil` — JSON Schema 2020-12 meta-schema check (`checkSchema`), value validation (`validate`, networknt json-schema-validator 3.x — already on the classpath via Spring AI, used through its String API so no Jackson 3 types leak), boot-time path check (`checkPath`), `typeOf()` (unwraps `[T, "null"]`), `toText()`, and the engine-fixed result schemas: SUPERVISOR `{pass, reason}`, ROUTER `{route (enum = routes keys), reason}`, APPROVAL `{decision (enum = routes keys), approver, comment}` |
| `common.loader` | `YamlDefinitionLoader` — SnakeYAML + Jackson `convertValue` from the definition folder's `workflows/**/*.yml`, `agents/**/*.md` and `mcp/**/*.yml` into the records above (`loadWorkflows()`/`loadAgents()` return `DefinitionFile(path, definition)`; `readTexts()` + `parseWorkflow/parseAgent(DefinitionText(path, text))` let the reloader parse unsaved text; error messages use the definition-folder-relative path) (with `${VAR}` substitution, uppercase names only so it never collides with `${input}`/`${state…}`). `readAgentFile()` splits an Agent `.md`: the first non-blank line must be `---`, the front matter runs to the next `---` line, everything after it (stripped) becomes `prompt` (env substitution applies there too). files that don't match `workflows/**/*.yml`, `agents/**/*.md`, `mcp/**/*.yml` are silently not loaded |
| `common.registry` | `WorkFlowRegistry`/`AgentRegistry`/`McpServerRegistry` — id/name → definition, plus `allowedCallers` (tenant) whitelist check. `AgentRegistry` (injects `ConfigTool`) requires `id`/`version`/a non-empty prompt body, meta-validates the compiled schemas, checks every closed-value field (`reasoning`; `temperature` 0–2; `context.sources`; `execution.*`) and `tools`/`subAgents`: `"*"` mixed with names, a `stepOnly` Tool named in `tools.allowed`, unknown sub agent id, a sub agent that itself has `subAgents` (depth is fixed at 1), a sub agent without `description`, or a sub agent id that isn't `[A-Za-z0-9_-]{1,64}` or collides with a Tool name all fail boot; an unregistered Tool name or a caller mismatch only warns. `modelOf(agent)` returns `model.name` or null. `WorkFlowRegistry` validates at startup, failing boot on the first error: `version`, the input schema, `state:` names `[A-Za-z_][A-Za-z0-9_]*`, `settings` (only `checkpoint: true`, `onError: STOP`, `maxIterations ≥ 1` — keys the engine does not implement are rejected, not ignored), step ids `[A-Za-z_][A-Za-z0-9_]*` and not `END`/`FAIL`, every `next`/`onFailure`/`routes` target, `agent` exists + step `with` shape matches the Agent's input schema, SUPERVISOR/ROUTER Agents declare no `output` and no `subAgents`, TOOL `with` arg names match the Tool's input schema (unknown Tool → warning, the only warning left), ROUTER/APPROVAL have ≥1 route, `forEach` is one whole expression; **saving**: every `save…` name is bare (a `state.` prefix gets a hint) and declared in `state:`, `saveEach` only on forEach steps, and every declared name is saved by some step; and for every expression in step `with`/`forEach`/Workflow `return`: valid path, root is `input`/`state`/a forEach variable, **the `state` name read is declared, and a storing step can run before the reading one** (reachability over `next`/`onFailure`/`routes`, so loops pass), and **field paths beyond that must exist** in the Workflow input schema / the single storing step's result schema (an error since 2026-10-18, it used to warn; not checked when several steps store the name, for TOOL results, `any`, or `saveEach` records). (The server-less `DefinitionFilesTest` that ran the same validation was deleted with the rest of the tests on 2026-10-12) |
| `common.config` | `Config`/`ConfigCallLog` (AOP call logging)/`ConfigChatClient` (single shared `ChatClient`)/`ConfigRedis`/`ConfigTool` (`@AiTool` bean scanning)/`ConfigMcp` (MCP client connections) |
| `common.session` | `RedisChatMemoryRepository` — Spring AI `ChatMemoryRepository` over Redis (system prompts are the Agent `.md` body — there is no separate prompt registry) |
| `common.security` | `ApiKeyAuthFilter`/`RateLimitFilter`/`CallerContext` |
| `runtime.workflow` | `WorkFlowExecutor` — the sequential/branch/parallel(`forEach`)/loop/approval-wait state machine; it resolves each step's `with` via `ContextResolver.resolve()` (forEach passes the item as `${item}`/`${<itemVariable>}`), calls the step executor, then **stores the outcome into `state` under the step's `save…` names** (`WorkFlowContext.saveOutput()` over `StepDefinition.output()` — written on success *and* failure, so a re-run step never leaves a stale value and a failed SUPERVISOR's `{pass: false, reason}` is readable; a result that is not saved is not readable by later steps); on `END` it resolves `return` (or returns the whole state). Its per-step "what next" decision is `nextStepId()` returning a step id or the `END`/`FAIL` sentinel. `runtime.workflow.execution` holds the persisted `WorkFlowExecution` (its `context` map = `CONTEXT_JSON` column = `{input, state, approvals, definition: {id, version}}`, `output` = `RESULT_TEXT` stored as JSON text)/`WorkFlowContext` (context-tree helpers)/`WorkFlowExecutionStatus`/`StepHistoryEntry`/`WorkFlowExecutionStore`. A run is **not pinned to the definition it started with**: on resume the currently registered definition is used and a version mismatch only logs a warning |
| `runtime.agent` | `AgentExecutor` — the one place that turns an `AgentDefinition` into a `ChatClient` call and enforces its contract: `call()` (validates input against `inputSchema()`, sends text as-is / anything else as JSON text, returns the raw reply for a string `outputSchema()` or a parsed+validated JSON value otherwise), `callForSchema()` (same input check, engine-given output schema — SUPERVISOR/ROUTER), `stream()` (string-output Agents only). Prompt slots use the **Workflow expression syntax** since 2026-10-21 (the user wanted one format for IN/OUT; `common.expression.PromptText` over `ContextResolver`, no Spring AI `PromptTemplate`): `${input}`/`${input.field}`/`${input.field:default}` = the Agent's own input (non-string as JSON text, missing → empty, so optional fields no longer fail), `${output.field}` = that output field's *name* (typo-checked), `${APP_HOME}` = env (loader), `\${` = literal, braces without `$` are plain text (JSON examples OK). `PromptText.check()` runs in `AgentRegistry.check()` (boot + designer [검사]): unknown field, any other root (`${state…}` → "put it in step `with`"), unresolved env, and old `{field}` matching an input/output name all fail with a hint. Chat API `variables` was removed the same day (its only use, `sample-general-chat`'s `{role}`, became fixed text) — Workflow state never reaches a prompt directly. This is not Dotprompt syntax: only Picoschema was borrowed from Dotprompt. The system prompt is always **engine rules + task prompt**: `runtime.prompt.EnginePrompt.compose()` puts fixed Java-constant rules (`COMMON` on every call, plus the caller-supplied `engineRule` — `SUPERVISOR`/`ROUTER`/`SUB_AGENT`; AGENT steps and the chat API pass `null`) in front of the Agent's rendered `prompt`, so YAML authors (possibly non-developers) can't drop them — there is deliberately no "role" enum, the caller just hands over the text. `buildSpec()` attaches only the Tools named in the Agent's `tools` list (∩ the caller whitelist; `["*"]` = all; chat `toolsEnabled` can only switch that list off, never widen it) and wraps each `subAgents` entry in a `SubAgentToolCallback` (Agent-as-Tool: name = agent id, description = `description`, args = input schema — non-object inputs are wrapped as `{input: ...}`; the child starts with an empty conversation and sees only the args; contract violations / exceeding `dstone.ai.agent.sub-agent.max-calls` (default 10) come back as `실패: ...` tool replies, system errors propagate; calls are logged by the callback itself because the self-invocation bypasses the `ConfigCallLog` proxy). `SchemaOutputConverter` (JSON Schema → format instruction + strict parse/validate), `AgentContractException` (contract violation → step failure / chat 400, as opposed to system errors → FAILED), and `ProviderErrorMessage` (appends the upstream provider name + real reason from OpenRouter's `error.metadata.raw` to a failed step's message, since the outer message is just `Provider returned error`; when the provider gave no detail it appends the exception's cause chain instead — `Error reading response (원인: IOException: ... <- ...)` — and `WorkFlowExecutor` writes the full stack to `execution.log` via `stackTraceOf()` rather than `printStackTrace()`, because a bare `Error reading response`/`Request failed` says nothing about who cut the connection). There are no `Verdict`/`RouteDecision` classes. A structured answer is accepted when it holds JSON matching the schema anywhere (`JsonAnswer.find`, last match wins, for prose or fences around it — seen 2026-11-02 on `sm-workflow` step02: a sentence before a correct `{pass, reason}` failed the run); otherwise `AgentExecutor.reshape()` makes one extra LLM call with no Tools, no memory and `reasoning: none` to move the answer into the schema (not for empty or `LENGTH`-cut answers; rule `EnginePrompt.RESHAPE`; on failure the original error stands) — it covers SUPERVISOR/ROUTER too, which have no `RETRY`, and repeats no Tool side effects. Scripted tests only; not run with a real LLM |
