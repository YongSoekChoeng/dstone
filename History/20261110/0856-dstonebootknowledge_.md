## 답변

"올린 문서"에 프로젝트 꼬리표를 붙이는 옵션입니다. 이 꼬리표는 위쪽 검색에서 문서가 보이는 범위를 정합니다.

**올릴 때 하는 일**
- 체크하면 위 "검색" 패널에서 지금 고른 프로젝트 ID가 `projectId`로 함께 전송됩니다 (`dstone-boot/src/main/webapp/knowledge/assets/js/search.js:119`).
- 서버는 그 프로젝트가 실제로 있는지 확인한 뒤 `rag_document.project_id`에 저장합니다 (`UploadDocumentService.java:86-89`). 없는 프로젝트면 오류가 납니다.
- 체크하지 않거나, 체크했어도 검색 쪽 프로젝트가 "(프로젝트 없이: 올린 문서에서만)"이면 `project_id`는 NULL로 저장됩니다. 어느 프로젝트에도 붙지 않은 문서가 됩니다.
- 올린 문서 목록의 "프로젝트" 열에 이 값이 나옵니다.

**검색 결과에 미치는 영향** (`RagDao.xml`의 `documentScope`, 544행)

| 검색할 때 고른 프로젝트 | "올린 문서"로 찾히는 문서 |
|---|---|
| 프로젝트 X | X에 붙여 올린 문서만 (붙이지 않은 문서와 다른 프로젝트 문서는 빠짐) |
| 프로젝트 없음 | 붙였든 안 붙였든 내가 올린 문서 전부 |

그래서 프로젝트를 골라 "코드 + 올린 문서"로 찾을 때 그 프로젝트의 설계서·매뉴얼만 코드와 함께 나오게 하려면 체크하고 올리면 됩니다. 붙이지 않은 문서는 검색에서 프로젝트를 비워야 찾을 수 있습니다.

**참고**
- 프로젝트와 상관없이 tenant 조건은 항상 적용됩니다. 인증을 켜 두면 API Key 호출자가 올린 문서만 보이고, 꺼 두면 tenant가 비어 있는 문서끼리만 보입니다.
- 문서 이름(`sourceId`)이 같은 파일을 다시 올리면 문서를 바꿔 넣으면서 프로젝트 꼬리표도 이번에 고른 값으로 바뀝니다. 붙였던 문서를 체크 없이 다시 올리면 꼬리표가 빠집니다.
- 문서를 프로젝트 분석에 넣는 기능은 아닙니다. 분석 결과(`analysis_*`)나 코드 청크와는 연결되지 않고, 검색 범위를 거르는 데만 쓰입니다.
