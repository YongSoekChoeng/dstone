# 현재까지의_메모리를_참고해서_모두_s

> 생성일시: 2026-10-01 09:17

## 질문

현재까지의 메모리를 참고해서 모두 skill로 만들어줘

---

## 답변

메모리 파일들을 먼저 읽고, 기존 skill 디렉터리 상태를 확인하겠습니다.

---

## 답변

메모리 9건을 각각 프로젝트 skill로 만들었습니다. 위치는 `/app/dstone/.claude/skills/<이름>/SKILL.md`이고, 아직 커밋하지 않았습니다.

| Skill | 원본 메모리 | 쓰이는 때 |
|---|---|---|
| `respond-in-korean` | Respond in Korean | 모든 응답·진행 안내 |
| `java-no-lambdas` | Avoid lambdas in Java | Java 소스 작성·수정 |
| `friendly-comments` | Friendly, plain-language comments | 주석 작성·수정 |
| `autowired-style-di` | Prefer @Autowired-style DI | 빈 주입, 조건부 빈 처리 |
| `no-systemd-app-scripts` | No systemd, use manual sh scripts | 앱 기동/중지 수단 추가·수정 |
| `jenkins-real-git-checkout` | Real git checkout, not local bypass | Jenkins SCM·체크아웃 설정 |
| `work-only-in-app-dstone` | Work only in /app/dstone | 파일 수정 전, 경로가 D:를 가리킬 때 |
| `cloud-architecture-wsl` | Cloud-native dstone on WSL project | 배포·k8s·프로파일·인프라 접속 문제 |
| `software-inventory-docs` | Software inventory docs | 소프트웨어 설치·설정 변경, 문서 작성 |

메모리 내용을 그대로 옮기지 않은 부분이 있습니다.

- **문서 경로를 현재 파일명으로 고쳤습니다.** 메모리에는 `docs/cloud-architecture.md`, `docs/environment.md`처럼 예전 이름이 적혀 있어서 `docs/04.cloud-architecture.md`, `docs/02.environment.md` 등으로 바꿨습니다.
- **지난 진행 상황은 뺐습니다.** 클라우드 프로젝트 메모리의 9월 4일자 "Jenkins SCM 전환 진행 중" 단계 목록, 미push 커밋 7건 같은 내용은 지금 맞는지 알 수 없어 넣지 않았고, 계속 유효한 구조와 운영상 함정만 남겼습니다.
- **`dstone-ai-engine`을 추가로 반영했습니다.** 메모리 작성 이후 생긴 `bin/` 스크립트와 Pod 배포 대상이라는 점을 `CLAUDE.md`와 실제 디렉터리 기준으로 넣었습니다.

알아 두실 점:

- **메모리 파일은 그대로 두었습니다.** 같은 내용이 메모리와 skill 양쪽에 있습니다. 메모리 쪽을 지우길 원하시면 말씀해 주세요.
- **`respond-in-korean`과 `work-only-in-app-dstone`은 메모리로 남겨 두는 편이 안전합니다.** skill은 설명에 맞는 작업일 때만 불려오지만 이 두 규칙은 항상 적용되어야 하기 때문입니다.
- **Stop 훅(`save-history.sh`)이 자동 커밋을 한다면** 이 파일들도 다음 history 커밋에 함께 들어갈 수 있습니다. 훅 내용은 확인하지 않았습니다.
