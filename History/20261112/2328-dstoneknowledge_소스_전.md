# 쉽고 친근한 주석 쓰기

주석은 한 번 읽고 바로 이해되어야 한다. 다시 읽어야 뜻이 잡히는 문장은 고쳐 쓴다.

## 오해하지 말 것

**주석을 줄이라는 뜻이 아니다.** 이 코드베이스는 원래 "왜 이렇게 했는지", 결정 배경, 이력을 길게 풀어 쓰는 한글 주석을 쓴다 (dstone-ai-engine의 `ConfigTool`, `CallerContext` 등). 그 관례는 그대로 이어간다. 바꾸는 것은 **말투와 문장**이다.

## 이렇게 쓴다

- 짧고 평범한 문장으로 끊어 쓴다.
- 딱딱한 한자어나 논문 같은 표현 대신, 구체적이고 직관적인 말을 고른다.
- "왜"는 그대로 남긴다. 표현만 쉽게 바꾼다.

```java
// 피한다
// 조건부 빈 등록에 기인한 의존성 부재 가능성을 고려하여 지연 조회 방식을 채택함.

// 이렇게 쓴다
// RAG를 꺼 두면 이 빈이 아예 없다.
// 그래서 꼭 필요할 때만 꺼내 쓴다.
```

## 답변

dstone-knowledge 소스 전체에 주석을 넣었고, 커밋해서 `origin/main`에 올렸습니다(`6e277d7c`).

**바뀐 것** (Java 파일 139개, 주석 약 1,900줄 추가)
- **메소드 설명:** 분석 단계(SCAN~DOCUMENT), RAG, 공통 코드, API(controller/service/dao)에서 설명이 없던 메소드에 한 줄 설명을 달았습니다. 마지막 검사에서 남은 건 매개변수 없는 예외 생성자 하나뿐입니다.
- **흐름 요약:** 주요 메소드(`run`, `startAnalysis`, `search`, `resolveFile`, `findFunctions` 등)의 Javadoc에 "흐름: 1) … 2) …"를 넣고, 같은 번호를 본문의 `// 1)`, `// 2)` 위치에 표시했습니다. 요약을 읽은 뒤 코드에서 해당 단계를 바로 찾을 수 있습니다.
- **행 클래스(`*Row`) 필드:** DB 스키마의 컬럼 설명에 맞춰 필드마다 뜻을 적었습니다.
- **DAO 메소드:** 각 메소드가 부르는 MyBatis SQL 위에 이미 있던 XML 주석을 그대로 가져왔습니다. XML 주석이 없는 약 70개는 직접 썼습니다.
- **형식:** 저장소 규칙대로 설명은 `<pre>`로 감싸고 `@param`은 그 뒤에 두었습니다. 문체는 짧고 쉬운 문장으로 맞췄습니다.

**작업하면서 고친 기존 주석 문제**
- `LombokExpander` 등 몇 곳: 줄 맨 앞의 `@Getter`, `@Query` 같은 글자를 Javadoc이 태그로 읽고 있어서 `&#64;`로 바꿨습니다. `LombokExpander`는 `</pre>`가 중간에 잘못 들어가 있던 것도 바로잡았습니다.
- `RagDao`: `selectViewLinksByFile`의 설명이 다른 메소드 위에 붙어 있어서 제자리로 옮겼습니다.

**검증**
- 주석과 공백을 뺀 코드를 HEAD와 비교했고, 139개 파일 모두 같았습니다. 코드는 한 글자도 바뀌지 않았습니다.
- `mvn compile`은 성공했습니다. 주석만 바뀌어서 테스트는 돌리지 않았습니다.

`SemanticPass.run`처럼 이미 직접 써 두신 큰 표 주석은 손대지 않았습니다. 기존 저장소 기록처럼 `main`에 바로 커밋했습니다.
