## 답변

네, 이번 변경에 맞춰 YAML도 모두 바꿨습니다.

**파일 현황**
- 변경 커밋 `c73c3fe`에서 옛 문법을 쓰던 YAML 16개가 수정됐습니다. Workflow 9개, Agent 7개입니다.
- 나머지 12개는 원래 옛 문법을 쓰지 않던 파일이라 고칠 필요가 없었습니다. Agent 6개와 `sample-router-multiway`, `sample-agent-tool-calling`, `sample-approval-pause-resume` 등 Workflow 6개입니다.
  - 이 파일들의 AGENT step에는 `input`이 없습니다. 이 경우 `{{previous.text}}`가 기본값으로 쓰여서 문제없습니다 (`WorkFlowExecutor.java:354`).

**바뀐 키**

| 옛 키 | 새 키 | 수정 건수 |
|---|---|---|
| `inputTemplate` (`{previous}` 문법) | `input` (`{{ }}` 문법) | 12건 |
| `structuredOutput` | `output` | 3건 |
| `forEachVariable` | `forEach` / `itemVariable` | 1건 |

**남은 옛 문법 확인**
- workflows와 agents 폴더 전체를 검색했는데 `inputTemplate`, `forEachVariable`, `structuredOutput`, `{previous}`, `__previous`가 하나도 없습니다.
- `sample-general-chat.yml`의 `{role}`은 Workflow 템플릿 문법이 아닙니다. 채팅 화면이 채워 넣는 system prompt 값이라서 그대로 둔 게 맞습니다.

**옛 키가 남아 있으면 기동에 실패합니다**
- `YamlDefinitionLoader`는 기본 설정의 `ObjectMapper`를 씁니다. 그래서 record에 없는 키가 있으면 해당 파일 경로를 담은 예외를 던지고 기동에 실패합니다.
- `WorkFlowRegistry`도 기동할 때 모든 `{{ }}` 참조를 검증합니다.
- 직전 세션에서 새 코드로 8081 엔진을 띄웠을 때 정상 기동했습니다. 전체 YAML이 새 문법으로 로드된다는 뜻입니다.

문서 `docs/09.dstone-ai-engine.md`에도 옛 이름(`structuredOutput`, `forEachVariable`)이 나오긴 합니다. 다만 모두 날짜가 붙은 과거 검증 기록이나 "폐지된 필드" 설명 안에 있는 것이라 고칠 대상은 아닙니다.
