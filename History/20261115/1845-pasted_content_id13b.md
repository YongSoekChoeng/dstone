## 답변

`SearchService`와 검색 화면 코드를 확인했습니다. 결론부터 말하면 오류나 장애가 아닙니다. **"이름만(KEYWORD)" 방법에서는 한글 낱말로 찾을 수 없다**는 뜻입니다.

## 1. 메시지의 의미

검색어는 서버에서 이렇게 처리됩니다 (`dstone-knowledge/.../rag/SearchKeywords.java`).

- 질문에서 **이름처럼 생긴 글자**만 골라냅니다. 영문자·숫자·`_`·`$`로 이어진 덩어리, 또는 `.`·`/`·`#`이 섞인 주소나 경로가 대상입니다.
- 길이가 **3자 이상**이고 **영문자가 하나 이상** 있어야 하며, 최대 8개까지 뽑습니다.
- **한글 낱말은 일부러 뽑지 않습니다.** 한글은 조사가 붙어서 글자가 그대로 맞는 경우가 드물고, 뜻으로 찾는 일은 벡터 검색이 더 잘하기 때문입니다.

`"샘플게시판"`에서는 따옴표도 한글도 이름 글자가 아니어서 뽑힌 이름이 0개입니다. KEYWORD 모드는 이름이 없으면 찾을 재료가 없으므로, `SearchService.java:128-130`이 400 오류와 함께 그 메시지를 돌려줍니다.

**해결 방법**
- **뜻 + 이름(HYBRID)** 또는 **뜻만(VECTOR)**으로 바꿔서 `샘플게시판`을 그대로 찾으세요. 한글은 뜻으로 찾는 쪽이 맡습니다.
- 이름만으로 찾으려면 영문 이름을 넣으세요. 예: `SampleBoardController`, `TB_SAMPLE_BOARD`, `/sample/board/list.do`

## 2. 조회조건 자세히

| 항목 | 의미 | 세부 동작 |
|---|---|---|
| **찾을 곳** | 어느 쪽에서 찾을지 | 프로젝트(예: testApp)를 고르면 **코드 분석 결과**에서, "(올린 문서)"를 고르면 **업로드한 일반 문서**에서 찾습니다. 한 번에 한쪽에서만 찾습니다. 프로젝트를 고르면 화면에서 리비전을 지정할 수 없어서, 그 프로젝트에서 **분석이 끝난 가장 최근 리비전**이 대상이 됩니다. |
| **방법** | 검색 방식 | 아래 표 참고 |
| **건수** | 돌려받을 결과 수 (topK) | 1~50이며 기본값은 10입니다. HYBRID로 찾으면 두 검색에서 각각 건수×3개(30~150개)를 넉넉히 뽑은 뒤 합쳐서 잘라냅니다. |
| **찾을 내용** | 질문 | 자연어 문장, 클래스·메소드 이름, 테이블 이름, URL을 섞어 써도 됩니다. 예: `OrderService.cancel 은 어디서 부르나` |
| **묶음** | (올린 문서일 때만 보임) | 문서를 올릴 때 붙인 묶음 이름(예: nexacro)으로 좁힙니다. |
| **종류** | (프로젝트일 때만 보임) | 메소드(METHOD) / 타입(TYPE) / SQL(MAPPER) / 화면(VIEW) / 파일(FILE) 가운데 체크한 종류만 찾습니다. 아무것도 체크하지 않으면 전부 찾습니다. |

### 방법(mode) 세 가지

| 방법 | 동작 | 장단점 |
|---|---|---|
| **뜻 + 이름 (HYBRID)**, 기본값 | 질문을 임베딩해서 뜻이 가까운 청크를 찾고(벡터), 질문 속 영문 이름이 **한 낱말로 그대로** 들어 있는 청크도 찾아서 순위로 합칩니다(`HybridRanker`). | 가장 무난합니다. 질문에 이름이 없으면 저절로 VECTOR처럼 동작하고, 결과 위 줄에 실제로 쓴 방법이 표시됩니다. |
| **뜻만 (VECTOR)** | 벡터 검색만 합니다. | 한글 질문에 맞습니다. 유사도가 기준(코드 **0.5**, 올린 문서 **0.35**)보다 낮은 결과는 버리기 때문에, 프로젝트와 상관없는 질문에는 결과가 0건일 수 있습니다. 결과 줄에 "버린 건수 / 가장 높았던 유사도"가 나와서 원인을 짐작할 수 있습니다. |
| **이름만 (KEYWORD)** | 임베딩 없이 이름 글자 맞춤만 합니다. | 임베딩이 아직 진행 중(PENDING)이거나 임베딩 서버(Ollama)가 내려가 있어도 동작합니다. 대신 영문 이름이 없으면 이번처럼 오류가 납니다. |

### 알아 두면 좋은 동작
- 이름 맞춤은 **한 낱말 단위**입니다. `deleteBoard`로 찾을 때 `deleteBoardAll`은 걸리지 않습니다. 대소문자는 구분하지 않습니다.
- `com.sample.BoardDAO#deleteBoard`처럼 쓰면 점과 `#`에서 나뉘어 `com`, `sample`, `BoardDAO`, `deleteBoard`가 각각 이름이 됩니다. 단, 3자 미만인 `com`은 빠집니다. 반대로 `/`가 들어간 주소는 통째로 하나의 이름으로 씁니다.
- HYBRID에서 임베딩 서버를 부르지 못하면, 질문에 이름이 있을 때는 **이름만으로 바꿔 찾고 경고**를 보여 줍니다. 이름이 없으면 503 오류가 납니다.
- 이 화면은 찾은 조각을 그대로 보여 줄 뿐이고, 답을 지어내지 않습니다.

`샘플게시판`은 HYBRID로 다시 찾아 보세요. 결과가 적다면 결과 위 줄의 "임베딩 PENDING" 숫자를 확인하세요. 임베딩이 아직 끝나지 않았을 수 있습니다.

## 답변

두 곳에 있습니다. 실제로 쓰는 값은 설정 파일에서 오고, Java 코드에는 설정이 없을 때 쓸 기본값이 들어 있습니다.

## 1. 설정 파일: `dstone-knowledge/conf/application.yml:127-135`

```yaml
dstone:
    knowledge:
        rag:
            search:
                min-score:
                    code: 0.5        # 코드 청크
                    document: 0.35   # 올린 문서
```

주석에 따르면 이 값은 임베딩 모델 **bge-m3로 실제 측정해서(2026-11-12)** 정했습니다.
- **코드는 0.5**입니다. 코드와 상관없는 질문(예: "대한민국 수도가 어디야?")의 1등 유사도는 0.34~0.47, 맞는 질문의 1등은 0.51~0.72였습니다.
- **올린 문서는 0.35**입니다. 사람이 쓴 글은 맞는 결과도 0.5를 못 넘는 경우가 많기 때문입니다. dstone-ai-engine의 RAG 기준값과 같은 값입니다.

임베딩 모델을 바꾸면 유사도 분포가 달라지므로 이 값을 다시 측정해야 합니다.

## 2. 읽는 코드: `dstone-knowledge/src/main/java/net/dstone/knowledge/rag/RagSettings.java:89-100`

```java
public double searchMinScoreCode() {
    return doubleProperty("dstone.knowledge.rag.search.min-score.code", 0.5);
}
public double searchMinScoreDocument() {
    return doubleProperty("dstone.knowledge.rag.search.min-score.document", 0.35);
}
```

yml에 값이 없거나 비어 있을 때만 두 번째 인자(0.5, 0.35)를 씁니다. 이 값으로 실제 거르는 곳은 `SearchService.search()`의 4단계(`score >= minScore`)입니다.

## 바꾸는 방법

- **서버 전체 기본값을 바꾸려면** `conf/application.yml`의 값을 고친 뒤 dstone-knowledge를 재시작합니다(`bin/stopApp.sh` → `bin/startApp.sh`).
- **요청 한 번에만 다르게 하려면** API 요청 본문에 `"minScore": 0.3`처럼 0~1 사이 값을 넣습니다. 그러면 코드와 문서 모두 그 값을 기준으로 씁니다. 0을 넣으면 거르지 않습니다.
  - 다만 dstone-boot의 **검색 화면에는 이 입력칸이 없습니다.** `search.js`가 `minScore`를 보내지 않기 때문에 화면에서는 항상 yml 값을 씁니다. 화면에서도 바꾸고 싶다면 입력칸을 추가해 드릴 수 있습니다.
- 이 기준은 **뜻으로 찾은(벡터) 결과에만** 적용됩니다. 이름으로 찾은(KEYWORD) 결과는 이름이 글자 그대로 맞은 것이라 거르지 않습니다.
