## 두 버그는 같은 실수에서 나왔습니다

둘 다 **참고 코드를 일부만 떼어 오면서, 그 코드가 어디서 어떻게 불리는지는 같이 가져오지 않은 것**입니다.

### 버그 1: `this.dataItem is not a function`

원본 `member.jsp`의 `memberRegi`는 이렇게 생겼습니다.

```js
selectedItem = this.dataItem($(e.target).closest("tr"));   // 39줄
...
command : [ { name: "edit", text: "수정", click : memberRegi } ]   // 329줄
```

이 코드가 동작하는 것은 **Kendo 그리드의 command 버튼이 `memberRegi`를 부르기 때문**입니다. Kendo가 부를 때 `this`를 그리드로 넘겨 줍니다.

설계 Agent는 함수 본문(`this.dataItem(...)`)만 가져왔습니다. 그리고 부르는 방법은 직접 만든 HTML 템플릿으로 바꿨습니다.

```js
template: ... onclick="imageBoardView.call(this, event)"   // this = <a> 요소
```

**서로 다른 호출 방식 두 개를 섞은 셈**이라, `this`가 그리드가 아닌 `<a>`, `<img>`가 됐습니다.

### 버그 2: 상세 팝업이 조회모드가 아니라 등록모드로 열림

| | 참고한 곳 | 동작 |
|---|---|---|
| 화면 쪽 | `member.jsp`의 `genexon.PopWindowOpen({data: selectedItem})` | 데이터를 `json_string` 하나로 묶어 URL에 붙임 |
| 서버 쪽 | `SampleBoardController` | 팝업 메서드가 없음. 그래서 VO 바인딩만 하는 Controller를 새로 씀 |
| 짝이 맞는 원본 | `MemberController.regiInscoPop`(98줄) | `json_string`을 `JSONObject.toBean`으로 푼다 |

설계 Agent가 실제로 읽은 파일을 로그에서 확인했습니다. `member.jsp`는 일부 구간만 읽었고, 그 화면이 부르는 `MemberController`의 팝업 메서드는 **한 번도 읽지 않았습니다.** 화면은 A 기능에서, 서버는 B 기능에서 가져왔기 때문에 둘이 주고받는 형식이 맞지 않았습니다.

## 왜 앞단계에서 걸러지지 않았나

- 컴파일 확인(step18)은 Java만 봅니다. 버그 1은 JSP 안의 JS 문제이고, 버그 2는 컴파일은 되지만 실행하면 값이 비는 문제입니다.
- 설계 승인(step13)에서 사람이 47초 만에 승인했습니다. 900줄 설계서에서 이런 문제를 보기는 어렵습니다.
- 그래서 실제로 눌러 보는 동작 검증에서 처음 드러났습니다. 게다가 한 번에 하나씩 드러났습니다. 1차 검증에서는 JS 오류 때문에 팝업이 아예 열리지 않아, 버그 2까지 갈 수 없었습니다.

## 고친다면

1. **`source-investigation` Skill에 범용 규칙을 넣습니다.** 이 Skill은 설계 Agent와 개발 Agent가 같이 쓰니, 앱에 묶이지 않는 내용으로 씁니다.
   - 참고 함수를 옮길 때는 그 함수를 누가, 어떻게 부르는지(이벤트 바인딩, `this`와 인자)까지 같이 옮긴다. 부르는 방식을 바꾸면 본문도 거기에 맞춘다.
   - 화면 참고를 정했으면, 그 화면이 부르는 URL의 Controller 메서드를 서버 참고로 삼는다. 화면과 서버의 참고를 서로 다른 기능에서 가져오지 않는다. `knowledgeCallers` 같은 Tool로 URL에서 Controller까지 따라간다.
2. 필요하면 영향도 Agent도 같은 Skill로 참고 파일을 화면·Controller 짝으로 짚게 합니다.
3. 고친 뒤에는 이번 경우를 엔진의 Agent 평가 사례(`conf/eval/**/*.eval.yml`)로 만들어 기준선과 비교합니다. 평가는 설계서에 `this.dataItem`을 쓰면서 HTML onclick에서 부르는지, 팝업 Controller가 `json_string`을 푸는지를 확인합니다. 지금은 `conf/eval` 폴더가 없어서 새로 만들어야 합니다.
