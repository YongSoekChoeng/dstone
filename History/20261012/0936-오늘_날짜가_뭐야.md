## 답변

원인은 스텝의 `type`입니다. `sm-workflow`의 `step00_02_decideJobKind`는 `AGENT`이고, `pilot-workflow`의 `step01`은 `ROUTER`입니다.

- **`ROUTER` 스텝**: 엔진이 `callForSchema()`로 호출하면서 답의 모양을 `{route, reason}` JSON으로 강제하고 파싱·검증합니다. 그래서 로그에 `{route=일반, reason=...}`으로 찍힙니다.
- **`AGENT` 스텝**: `call()`로 호출하고, 답의 모양은 Agent YAML의 `output` 선언을 따릅니다. `sm-decide-job-kind-agent`에는 `output`이 없어서 기본값인 텍스트로 처리됩니다.

로그의 `**route:** 일반**reason:** ...`은 LLM이 프롬프트를 흉내 내어 쓴 마크다운 문장일 뿐입니다. 그 문장 전체가 `state.classify.route`에 문자열로 저장됩니다.

`sm-decide-job-kind-agent.yml`의 주석과 `description`에는 "ROUTER 전용"이라고 적혀 있지만, 실제 동작은 워크플로 쪽 `type`이 결정합니다.

## 고치는 방법 (둘 중 하나)

**1. 스텝을 ROUTER로 바꾸기** — 분류 결과로 경로를 가를 생각이라면 이쪽이 맞습니다.

```yaml
- id: step00_02_decideJobKind
  type: ROUTER
  agent: sm-decide-job-kind-agent
  input: "${state.request}"
  output:
    result: "state.classify"        # {route, reason} 전체가 들어감
  routes:
    신규개발: <다음 step id>
    일반: <다음 step id>
  onFailure: FAIL
```

`ROUTER`는 `next` 대신 `routes`가 1개 이상 필요합니다. 값은 `END`도 가능합니다.

**2. AGENT로 두고 Agent에 출력 계약 선언하기** — 분기 없이 값만 받고 싶을 때입니다.

```yaml
# sm-decide-job-kind-agent.yml
output:
  format: JSON
  schema: schemas/sm/sm-decide-job-kind.schema.json   # {route: enum[신규개발, 일반], reason: string}
  validation: STRICT
```

이 경우 워크플로의 저장 위치도 `result: "state.classify"`로 바꿔야 `state.classify.route`로 읽을 수 있습니다. 또 이 Agent는 `output`을 선언했으므로 ROUTER 스텝에서는 쓸 수 없게 됩니다(부팅 실패).

원하시는 방향을 알려주시면 바로 수정하겠습니다.
