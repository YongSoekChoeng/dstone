## 답변

화면의 승인·반려는 이 step의 실제 선택지가 아닙니다. **실행이 기다리는 사이에 Workflow 정의가 바뀌었고, 승인 처리 코드가 step을 id가 아닌 순번으로 찾아서** 생긴 엔진 결함입니다.

**원인**

이 실행은 `sm-workflow` 2.13.1로 시작했고 DB에는 `current_step_index = 18`, `currentStep = step19`가 저장돼 있습니다. 2.14.0에서 앞쪽에 `step63`(검증 누적 결과 비우기)이 추가되면서 순번이 하나씩 밀렸습니다.

| 순번 18이 가리키는 step | 종류 |
|---|---|
| 2.13.1: `step19` 개발 승인 | APPROVAL |
| 2.14.0: `step18` 컴파일 확인 | TOOL |

1. `pendingApproval()`(`WorkFlowExecutionService.java:624`)이 순번 18의 step을 꺼냅니다. APPROVAL이 아니므로 `null`을 돌려줍니다.
2. 화면(`workflow-admin.js:1442`)은 선택지가 없으면 승인 방식으로 보고 **승인·반려를 기본으로** 그립니다.

실행 중인 서버에 2.14.0이 로드돼 있다는 것은 증상과 코드로 추정한 것이며, 서버에서 직접 확인하지는 않았습니다.

**지금 화면에서 눌러도 진행되지 않습니다.** `decide()`(`WorkFlowExecutionService.java:224`)도 같은 방식으로 찾기 때문에 "APPROVAL step이 아닙니다"라는 409로 거절됩니다.

**해결 방법**

1. **이 실행만 풀기:** DB의 순번을 2.14.0 기준인 19로 바꿉니다. 그러면 6개 선택지가 나옵니다.
   ```sql
   UPDATE ai_workflow_execution SET current_step_index = 19
    WHERE execution_id = '5def8189-1115-4de9-86e1-25d038de0d6e'
      AND status = 'WAITING_APPROVAL' AND current_step_index = 18;
   ```
   이후는 2.14.0으로 돕니다. 새로 생긴 검증 누적 값(`verificationAll`)은 비어 있어, 재개발을 고르면 지난 회차 결과가 누적에 들어가지 않은 채 검증합니다.

2. **엔진 고치기:** `decide()`와 `pendingApproval()`이 `resumePoint()`처럼 저장된 step id로 찾게 합니다. `resumePoint()`에는 이미 "멈춘 사이 step을 끼워 넣어도 엉뚱한 step이 돌지 않게" 하는 처리가 있는데 승인 경로에만 빠져 있습니다. 화면도 `pendingApproval`이 없으면 승인·반려를 그리지 말고 이유를 보여 주는 편이 맞습니다.

2번까지 반영해 서버를 다시 띄우면 DB를 손대지 않아도 이 실행이 풀립니다. 그래서 **2번을 권합니다.** 급하면 1번을 먼저 적용하면 됩니다. 어느 쪽을 진행할까요? 아직 코드와 DB는 바꾸지 않았습니다.

## 답변

네, 맞습니다. 재개발 comment는 개발 Agent에게 **이번 일의 지시**로 전달되고, 설계서보다 우선합니다.

**전달 경로**

`step19`(재개발 + comment) → `step20`(설계서·태스크아이템 다시 읽기) → `step17`(개발, `sm-developer-agent`)

- `step17`은 comment를 `instruction: ${arrival:}`로, 지금까지의 결정 전체를 `history`로 받습니다.
- 개발 Agent 프롬프트(2.6.0)에는 "재개발에서는 사람의 지시가 설계서보다 앞선다"고 적혀 있습니다.
- 공통 Skill `handling-instructions`는 되돌리기 결정의 의견을 "이번 일의 핵심이다. 빠짐없이 반영한다"고 정합니다.

**동작 방식**

| 항목 | 내용 |
|---|---|
| 고치는 범위 | 기존 `dev-resources`에서 지시와 관련된 곳만 고칩니다. `완료` 항목도 관련 있으면 다시 확인합니다. |
| 설계서 | 고친 내용을 `03-1.design.md`에 옮기고 수정 이력을 남깁니다. |
| 컴파일 오류 | 직전 오류가 있으면 그것을 먼저 고칩니다. |
| 반영하지 못한 지시 | 답의 `notApplied`에 이유와 함께 적습니다. |
| 재검증 | `step35`가 comment를 `reported`로 받아 "사람이 알린 오류" 기준을 맨 앞에서 재현합니다. |

**알아 둘 점**

- 이 우선순위는 엔진이 강제하는 것이 아니라 **프롬프트와 Skill의 지시**입니다. 다음 승인 때 `notApplied`와 "사람이 알린 오류"의 판정을 확인하세요.
- comment는 필수가 아닙니다. 비워 두면 Agent가 무엇을 고칠지 알 수 없으니 꼭 적으세요.
- `step57`(보류 이어서 개발)과 `step58`(형식 오류 고치기)에서는 comment가 `instruction`이 아니라 `history`로만 전달됩니다.
- 컴파일 확인(`step18`)이 실패하면 검증 없이 `step19`로 돌아옵니다.

**comment에 적으면 좋은 내용**

```
[화면] 회의실 예약신청 팝업
[재현] 1) 타임테이블에서 빈 슬롯 클릭  2) …
[실제] 시작시간·종료시간이 undefined로 보임
[기대] 클릭한 슬롯의 시간이 채워짐
[오류] 서버 로그, 브라우저 콘솔, 네트워크 응답
```

원인을 짐작해서 쓰기보다 관측한 증상과 로그를 그대로 붙이는 편이 정확합니다. 오류가 여러 개면 번호를 매겨 적으세요. 코드가 아니라 설계가 틀린 문제라면 `설계 수정`을 고르는 것이 맞습니다. 이 경우에는 개발 폴더를 비우고 설계서대로 다시 만듭니다.

## 답변

재개발할 때는 검증 수준을 **고르지 않습니다. 항상 전체 확인**(테스트 서버를 띄우고 화면을 눌러 확인)입니다.

**정해지는 방식**

검증 수준은 `step19` 개발 승인이 아니라 앞선 `step13` 설계 승인에서 고릅니다. 이 선택은 첫 검증에만 적용됩니다. `step43`에 `limit.max: 1`이 걸려 있어, 두 번째부터는 설계 승인의 선택을 보지 않고 `step41`로 갑니다.

| 설계 승인에서 고른 값 | 첫 검증 | 재개발 후 검증 |
|---|---|---|
| 전체 확인 | 화면 검증 | 화면 검증 |
| 간이 확인 | 서버 기동만 확인(`step45`) | 화면 검증 |
| 최소 확인 | 서버 없이 개발 승인으로 | 화면 검증 |

**재개발 흐름**

`step19` 재개발 → `step20` → `step17` 개발 → `step18` 컴파일 → `step53` 형식 확인 → `step28` 리비전 확인 → `step60` DDL 확인 → `step43`(건너뜀) → `step41` → `step40` 바뀐 파일 확인 → `step29` 서버 기동 → `step35` 동작 검증

`step35`는 사람이 알린 오류, 바뀐 파일과 관련된 기준, 지난번 `FAIL`·`BLOCKED`, 나머지 순으로 확인합니다.

**화면 검증까지 가지 않는 경우**

| 상황 | 이동 |
|---|---|
| 컴파일 실패 | `step19` |
| 테스트할 리비전이 없음 | `step19` |
| DDL이 개발 DB에 없음 | `step61`에서 반영 후 계속하거나, `테스트 없이 진행`으로 `step19` |
| 서버 기동 실패(개발 결과 탓) | 자동 수정 흐름(`step32` → `step34`) |
| 서버 기동 실패(그 밖의 원인) | `step19` |

**주의할 점**
- 첫 검증까지 가 본 적이 없으면(예: 컴파일 실패로 `step19`에 온 뒤 재개발) 첫 검증으로 쳐서 설계 승인의 선택이 적용됩니다.
- 이 횟수는 실행 전체에서 셉니다. `설계 수정` 후 설계 승인에서 `간이 확인`을 다시 골라도, 이미 `step43`을 한 번 지났다면 화면 검증을 합니다.
- 문구 하나만 고치는 재개발도 화면 검증을 하며, 현재 정의에는 이를 낮추는 선택지가 없습니다.

실행 `5def8189-…`도 지난 재개발에서 `step43`의 한도를 다 써 `step41`로 갔습니다. 이번에 다시 재개발해도 화면 검증을 합니다. 재개발에서도 수준을 고르고 싶다면 Workflow 정의를 바꾸면 됩니다.
