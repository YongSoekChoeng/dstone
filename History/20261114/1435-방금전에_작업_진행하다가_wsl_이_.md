채팅 화면의 도구호출(Tool) 칸을 Agent 관리 팝업과 같은 모양으로 바꿨고, Tool 찾기 창은 종류별(소스 RAG / 문서 RAG / MCP / 일반) 표로 보이게 했습니다. ai-engine 테스트 153개는 실패 없이 통과했고, 두 앱은 새로 빌드해 다시 띄워 두었습니다.

**바뀐 화면**
- **채팅의 도구호출 칸**: 고른 Tool은 칩으로 보입니다(종류 표시 + 이름 + ×). [+ 찾아서 추가]를 누르면 Tool 찾기 창이 열립니다. 기존의 [올린 문서 찾기]·[모두 선택]·[모두 해제] 버튼은 창의 기능으로 대신해 없앴습니다.
- **Tool 찾기 창**:
  - 종류마다 표가 하나씩 있고, 칸은 체크박스 / Tool 이름 / 설명입니다.
  - 위쪽 탭(전체·소스 RAG·문서 RAG·MCP·일반)으로 한 종류만 볼 수 있습니다. 탭에는 "고른 수/전체 수"가 같이 나옵니다.
  - 표 머리의 체크박스로 그 종류를 한꺼번에 고르거나 뺍니다.
  - 검색 칸, [고른 것만], [모두 빼기]가 있습니다. [고르기]를 눌러야 반영되고, [취소]나 Esc는 고친 것을 버립니다.
- **디자이너 Agent 관리 팝업**: Tool의 [+ 찾아서 추가]도 같은 창을 씁니다. Skill과 Sub Agent는 예전 고르기 창 그대로입니다.

**종류는 엔진이 정합니다**
- `@AiTool`에 `category` 속성을 추가했습니다. MCP 서버에서 온 Tool은 자동으로 MCP가 됩니다. 종류는 화면에서 묶어 보여 주는 데만 쓰고 실행에는 영향이 없습니다.
- 한 클래스에 종류를 하나만 붙일 수 있어서, 문서 Tool 세 개를 `KnowledgeTool`에서 새 클래스 `KnowledgeDocTool`로 분리했습니다. Tool 이름은 그대로라 Agent·Workflow 정의 파일은 고칠 필요가 없습니다.
- **채팅 API 응답 형식이 바뀌었습니다.** `GET /api/ai/chat`의 `availableTools`가 이름 목록에서 `{name, description, category}` 목록으로 바뀌었습니다. 이 API를 쓰는 곳은 boot뿐이라 boot도 함께 고쳤습니다. 디자이너 카탈로그에도 `category`가 붙습니다.

**확인한 것**

- 로그인 없이 볼 수 있게, 실제 CSS·JS와 이 데이터로 시험 페이지를 만들어 headless 브라우저로 찍어 봤습니다. 처음 찍었을 때 설명 칸의 표 테두리가 어긋나 있어서 고친 뒤 다시 배포했습니다.
