## 답변

현재 화면 코드(`index.jsp`, `project.js`, `knowledge-terms.js`의 `SECTIONS`)를 확인한 뒤 의견을 정리했습니다.

## 지금 화면이 어수선해 보이는 이유

1. **표 순서가 사용자의 질문이 아니라 응답 JSON 구조를 따릅니다.**
   지금 순서는 `relations.*` → `semantic.*` → `files.*` → `declarations.*` → `passes` → `rag.*` → `jobs`입니다. 사용자가 실제로 묻는 것은 "써도 되나?", "왜 안 이어졌나?", "무엇이 잡혔나?", "어떻게 돌았나?" 정도인데, 표 18개가 같은 무게로 한 줄에 늘어서 있습니다.
2. **같은 내용이 여러 곳에 나옵니다.**
   - 임베딩: 맨 위 `임베딩 현황` 패널, "한눈에 보기"의 임베딩 줄, 맨 아래 `임베딩 진행` 표까지 세 곳에 있습니다.
   - "풀지 못한 참조 살펴보기" 버튼: 한눈에 보기 바로 아래와 "풀지 못한 참조의 이유" 표 뒤에 두 번 나옵니다(`project.js:372`, `:383`).
   - 품질: `품질 지표` 표, 한눈에 보기, 적용 진단이 같은 숫자를 세 번 보여 줍니다.
   - 단계: Job 박스의 단계 진행, `단계별 진행`, `파일별 단계 결과`가 겹칩니다.
3. **작업하는 곳과 결과를 보는 곳이 한 흐름에 섞여 있습니다.** 등록 폼, 분석 시작 폼, 리비전 목록, 요약, 조사 패널이 모두 세로로 이어집니다.
4. **진단용 표가 앞에 그대로 나와 있습니다.** 인코딩, 소스 루트, 문법 수준, 자동 생성 멤버의 출처는 문제가 생겼을 때만 볼 표인데, 품질 지표와 같은 높이에 있습니다.

## 제안: "작업 영역"과 "리비전 상세(탭 5개)"로 나누기

```
프로젝트 · 분석
├─ [상단 바] 프로젝트 선택 ▾ | 상태 배지 | 임베딩 배지(예: 임베딩 82%) | [등록/수정] (접힘)
├─ 분석 실행        라벨 · 다시 시작할 단계 · 증분 분석 · [분석 시작]
│                   └ 진행 중인 Job (분석이 돌 때만 보임)
├─ 리비전 목록      표 + 보관 정책 (행을 고르면 아래 상세가 열림)
└─ 리비전 상세 #12 ─ 탭
     ① 개요         숫자 카드 5개 · 한눈에 보기 · 적용 진단(할 일 목록)
     ② 연결 품질 ⚠  관계(종류·신뢰도) · 참조 · 풀지 못한 참조의 이유
                    [풀지 못한 참조] [짐작으로 이은 참조] → 이 탭 안에서 열림
     ③ 분석 내용    진입점 · 계층 · Java 밖의 자원 · 타입 · 멤버(+자동 생성 출처)
     ④ 소스 파일    파일(종류별) · 인코딩 · Java 소스 루트 · 문법 읽기 결과
     ⑤ 실행 기록    단계(진행 + 파일별 결과를 합침) · 증분 분석 · 검색 문서/임베딩 · Job 이력
```

### 묶는 기준
- **개요**: 이 리비전을 써도 되는지, 무엇을 고쳐야 하는지. 대부분의 사용자는 여기서 끝납니다.
- **연결 품질**: 분석률을 올리려는 사람이 보는 곳. 원인 표와 살펴보기 패널이 같은 탭에 있어야 흐름이 끊기지 않습니다.
- **분석 내용**: 결과물(진입점, 계층, SQL 같은 자원, 타입)의 목록.
- **소스 파일**: 입력이 제대로 들어갔는지. 문제가 있을 때만 엽니다.
- **실행 기록**: 운영자용 이력.

### 합치거나 없앨 것
| 지금 | 바꾼 뒤 |
|---|---|
| `품질 지표` 표 | 개요의 카드와 한눈에 보기에 흡수하고, 원래 표는 "지표 원본 보기"로 접어 둠 |
| `임베딩 현황` 패널 + `임베딩 진행` 표 + 한눈에 보기 줄 | 상단 바에 배지 하나, 자세한 내용은 ⑤ 한 곳 |
| 살펴보기 버튼 두 벌 | ② 탭에 한 벌 |
| `단계별 진행` + `파일별 단계 결과` | "단계" 표 하나(단계 · 상태 · 처리/건너뜀/실패 수 · 시간) |
| `자동 생성 멤버의 출처` | `멤버` 표 아래 접힌 하위 표 |

### 덧붙이고 싶은 장치
- **탭 이름에 경고 표시**: 적용 진단에서 warn/bad가 나온 영역의 탭에 ⚠를 붙입니다. 열어 보지 않아도 어디를 봐야 할지 알 수 있습니다.
- **접힌 표 제목에 한 줄 요약**: 예를 들어 `진입점 — HTTP 120 · BATCH 3`, `인코딩 — UTF-8 940 · EUC-KR 12`처럼 씁니다. 표를 펼치지 않아도 핵심 숫자가 보입니다.
- "이 표 읽는 법" 접기는 지금처럼 둡니다.

### 정해 주실 것
1. **탭이냐, 접히는 묶음(아코디언)이냐.** 저는 탭을 권합니다. 한 번에 한 가지 질문만 보이니 정돈된 느낌이 가장 큽니다. 다만 여러 탭을 오가며 비교하기는 불편해집니다.
2. **등록/수정 폼과 리비전 목록의 위치.** 위 안처럼 세로로 두는 방식과, 왼쪽에 프로젝트·리비전 목록을 두고 오른쪽에 상세를 두는 2단 구성이 있습니다. 2단이 더 정돈돼 보이지만 손댈 곳이 커집니다.

이 방향이 괜찮으면 `index.jsp`, `project.js`, `knowledge-terms.js`의 `SECTIONS`에 탭 정보를 넣는 식으로 고치고, 사용 안내(`guide.js`)와 `docs` 쪽 설명도 함께 맞추겠습니다.
