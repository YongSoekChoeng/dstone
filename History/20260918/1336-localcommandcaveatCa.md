## 3. Java files by package

**`net.dstone.ai` (root)**
- `DstoneAiEngineApplication.java` — `@SpringBootApplication`, `@ComponentScan("net.dstone.ai")`; loads `env[-profile].properties` into System properties, then boots with `spring.config.location`/`logging.config` pointed at `APP_CONF_DIR`.

**`api.controller`**
- `ChatController` — `POST /api/ai/chat` (single Agent call) and `/api/ai/chat/stream` (SSE); resolves session/caller, delegates to `AgentRegistry`+`AgentExecutor`; computes the "effective model" for the response.
- `RagController` — `/api/ai/rag/documents` (POST ingest/DELETE), `/api/ai/rag/search` — admin/debug endpoints around `RagService`, always registered regardless of `dstone.ai.rag.enabled`.
- `WorkflowController` — `/api/ai/workflow/{id}/execute` (sync), `/{id}/submit` + `/status/{jobId}` (async via `AsyncJobService`); validates workflowId/caller before dispatching.

**`api.dto`**
- `ChatRequest`/`ChatResponse` — chat contract incl. per-request `ragEnabled`/`toolsEnabled`/`model` overrides.
- `IngestResponse`, `RagSearchRequest`, `RetrievedChunk` — RAG DTOs.
- `WorkflowRequest`/`WorkflowResponse`/`WorkflowSubmitResponse`/`WorkflowStatusResponse` — workflow contracts; status is one of RUNNING/DONE/FAILED with result/error fields.

**`api.service`**
- `AsyncJobService` — submit/status polling for async workflows; `CompletableFuture.runAsync()` on the **default common ForkJoinPool** (explicitly flagged as MVP-only, no dedicated executor/queue/concurrency limit); job state stored as a Redis Hash (`dstone:ai:workflow:job:{jobId}`, 1h TTL). **No pause/resume — a submitted job runs start-to-finish uninterrupted.**

**`common.annotation`**
- `AiTool` — marker annotation (meta-annotated `@Component`) that lets any bean's `@Tool` methods be auto-discovered by `ConfigTool`.

**`common.config`**
- `Config` — `@Import`s all Configuration classes in the module (works around `@ComponentScan` boundary with `dstone-common`).
- `ConfigCallLog` — AspectJ `@Aspect` for method-entry/exit logging across Controller/Service/DAO/runtime/tools packages (honors `@NoAspectLog`).
- `ConfigChatClient` — assembles the single shared `ChatClient` bean: `ChatMemoryRepository` (Redis or in-memory fallback), `ChatMemory` (sliding window via `dstone.ai.session.max-messages`), `List&lt;Advisor&gt;` (currently just `SimpleLoggerAdvisor` + `MessageChatMemoryAdvisor` — explicitly the governance/PII extension point since consumers can add more `@Bean Advisor`s).
- `ConfigRedis` — `RedisTemplate` bean via `dstone-common`'s `RedisUtil`, conditional on `spring.data.redis.enabled=true`.
- `ConfigTool` — scans `@AiTool` beans at `@PostConstruct`, builds a `ToolCallbackProvider`; applies per-caller whitelist (`dstone.ai.tool.allowed-by-caller`), used both for AGENT-step tool-calling and TOOL-step direct lookup (`findByName`).

**`common.consts`**
- `Constants` — all static config-prefix/key constants (AsyncJob keys/TTL, Security auth/ratelimit prefixes, Session Redis key prefix, Tool prefixes, Workflow `DEFAULT_MAX_ITERATIONS=5`/`SUCCESS`/`FAIL` sentinels, Outcome `"실패"` fail-prefix convention, RAG metadata keys, YAML classpath location patterns).

**`common.definition`** (pure records, no logic)
- `AgentDefinition(name, promptName, description, model, toolsEnabled, ragEnabled, allowedCallers)`
- `StepDefinition(id, type, ref, parallelGroup, onFailure, onSuccess, inputTemplate)`
- `StepType` enum — `AGENT` (always succeeds), `RAG` (search-only, no LLM), `TOOL` (deterministic, "실패"-prefix judged), `SUPERVISOR` (LLM judged via structured `Verdict`)
- `WorkFlowDefinition(id, description, maxIterations, allowedCallers, steps)`

**`common.exec`**
- `ExternalProcessRunner` — shared safe process runner for shell/python tools; uses `ProcessBuilder` directly (no shell interpolation), enforces timeout and output-size truncation, "통과:/실패:" convention.

**`common.loader`**
- `YamlDefinitionLoader` — resolves `classpath*:workflows/*.yml` and `classpath*:agents/*.yml` via `PathMatchingResourcePatternResolver`, parses with SnakeYAML, binds to definition records via Jackson `ObjectMapper.convertValue()` (relies on `-parameters` compiler flag).

**`common.prompt`**
- `PromptProperties` — resolves per-template prompt version (`dstone.ai.prompt.versions.{name}`, else `default-version`).
- `PromptTemplateRegistry` — loads/caches `classpath:prompts/{name}/{version}.st` as Spring AI `PromptTemplate`, renders with variables.

**`common.registry`**
- `AgentRegistry` — `@PostConstruct` loads all agents into a `Map&lt;name, AgentDefinition&gt;` (dup names fatal), `resolve(name, caller)` enforces `allowedCallers` whitelist.
- `WorkflowRegistry` — same pattern keyed by workflow `id`.

**`common.security`**
- `ApiKeyAuthFilter` (`@Order(1)`) — `X-API-Key` header check, opt-in via `dstone.ai.security.auth.enabled`; bypasses `/actuator/**`; sets `CallerContext` on success. No Spring Security — module excludes it entirely.
- `RateLimitFilter` (`@Order(2)`) — fixed-window Redis counter per caller/IP, opt-in via `dstone.ai.security.ratelimit.enabled`; throws if enabled without Redis.
- `CallerContext` — static helper storing/reading `caller` as a request attribute (same key reused as ChatClient Advisor context key, though not yet consumed by any advisor).

**`common.session`**
- `RedisChatMemorySession` — implements Spring AI's `ChatMemoryRepository` SPI directly over `RedisTemplate` (no official Spring AI Redis repo exists); one Redis List per conversation (`dstone:ai:session:{conversationId}`) + a `Set` index of conversation IDs; **`TOOL`-type messages throw `IllegalStateException`** on deserialize (tool-calling itself works, but its result-message persistence to Redis is unimplemented).

**`rag`**
- `RagService` — single class handling ingest (Tika extract → `TokenTextSplitter` chunk, or raw JSONL passthrough for `.json/.jsonl` sources) → pgvector upsert-by-`sourceId`; delete; similarity search; and building the `QuestionAnswerAdvisor` used by `AgentExecutor` when `ragEnabled`. Tenant isolation via `tenant` metadata filter keyed on `caller`. Gate: `requireVectorStore()` throws unless `dstone.ai.rag.enabled=true` AND a `VectorStore` bean actually exists.

**`runtime`**
- `WorkflowContext` — mutable `Map&lt;String,Object&gt;` shared across steps (`input`, `result`, `variables` by convention).
- `WorkflowExecutor` — the state machine driving sequential/branch/parallel/loop execution; enforces `maxIterations`; resolves `parallelGroup`s via `CompletableFuture`; success/failure transition logic (`SUCCESS`/`FAIL` sentinels, loop-vs-next by step index comparison).
- `StepFlow`, `StepStatus` (`NEXT_STEP`/`LOOP`/`SUCCESS`/`FAIL`), `StepOutcome(success, text)`, `Verdict(pass, reason)` — supporting value types for the state machine and SUPERVISOR structured judgment.

**`runtime.agent`**
- `AgentExecutor` — the single place that assembles a `ChatClient` request from an `AgentDefinition` (session-id advisor param, system prompt render, conditional RAG advisor, conditional tools, model override, caller advisor placeholder marked `TO-DO`). Exposes `call()`, `stream()`, `callForVerdict()` (uses `.entity(Verdict.class)` for structured SUPERVISOR output).

**`runtime.step`**
- `AgentStepRunner` — runs AGENT (always success) and SUPERVISOR (fail-closed on `Verdict.pass()==false` or parse exception) steps.
- `ToolStepRunner` — runs TOOL steps: strips LLM artifacts (code fences, `[label]` prefixes) from previous-step text, renders `inputTemplate` (`{previous}`/`{varName}` substitution with JSON-escaping), calls `ToolExecutor`, judges success by `"실패"` prefix.
- `RagStepRunner` — pure search step, concatenates retrieved chunk texts, no LLM call.

**`runtime.tool`**
- `ToolExecutor` — single choke point for LLM-free TOOL-step invocation; unwraps Spring AI's JSON-wrapped string tool result before prefix-checking; explicitly called out as the governance/audit extension point.

**`tools.*`**
- `tools.sample.DateTimeTools` — sample `getCurrentDateTime()` tool.
- `tools.sql.SqlSyntaxTools` — `validateSqlSyntax()` using JSQLParser (pure grammar check, no live DB); always active (no whitelist needed).
- `tools.shell.ShellExecTool` / `tools.python.PythonExecTool` — whitelist-only script execution (`allowed-commands`/`allowed-scripts` config maps name→path); disabled by default since whitelist is empty.
- `tools.http.HttpCallTool` — whitelist-only HTTP GET (`allowed-hosts`); disabled by default.

### Quick synthesis for your restructure decision
The current engine is a clean, recently-rewritten (2026-09-15), fairly minimal 4-layer design (Workflow→Step→Agent→Tool, all YAML-declared) with working sync/async execution, RAG, session memory, and opt-in auth/rate-limit — but it has **zero** HITL/approval infrastructure and **zero** MCP integration; both would need to be designed from scratch.
