## 답변

방금 디스크에서 바뀐 부분이 문제입니다. `renderToolInput()`이 이렇게 바뀌었습니다:

```java
if( StringUtil.isJson(input) ) {
    rendered = inputTemplate.replace("{previous}", this.jsonEscape(input));
}else {
    rendered = inputTemplate.replace("{previous}", input);   // <- 이스케이프 없이 그대로 삽입
}
```

이 조건이 제가 방금 고친 JSON 이스케이프 버그를 사실상 무력화시킵니다. `{previous}`는 `{"sql":"..."}` 템플릿 안에 **JSON 문자열 값으로 끼워넣을** 텍스트인데, 그 텍스트 자체가 독립적으로 유효한 JSON 문서인지 여부는 이스케이프가 필요한지와 아무 상관이 없습니다. 지금 로그의 입력값(마크다운 코드펜스 + 여러 줄 SQL)은 당연히 `isJson()`이 `false`를 반환하므로 else 분기로 빠져서 이스케이프 없이 raw 텍스트가 그대로 삽입되고, 백틱 안의 줄바꿈 때문에 JSON이 깨져서 똑같은 파싱 오류가 재발한 겁니다. (참고로 51번 줄 `rendered = ...jsonEscape(input)`도 바로 다음 if/else에서 덮어써지는 죽은 코드입니다.)

`isJson` 분기 자체가 목적에 안 맞는 조건이라, 이 분기를 걷어내고 항상 `jsonEscape(input)`을 쓰도록 되돌리는 게 맞다고 봅니다. 이대로 수정할까요?

방금 로그가 왜 계속 똑같은지 확인했습니다 — **prompt 수정이 실제 실행 중인 서버에 반영된 적이 없습니다.**

증거:
- `target/classes/prompts/oracle-to-postgresql/v1.st` (14:44에 빌드된 옛 버전) vs `src/main/resources/.../v1.st` (15:23, 지금까지 고친 내용) — 서로 다릅니다. 즉 마지막 빌드 이후로 rebuild가 한 번도 안 됐습니다.
- 이 호스트에 `dstone-ai-engine` 프로세스 자체가 안 보입니다(포트 8081도 없음). CLAUDE.md 아키텍처상 dstone-ai-engine은 `kind` 클러스터의 Pod로 떠 있는데, Pod는 애초에 소스 디렉토리를 직접 보지 않고 **빌드된 이미지** 안의 리소스만 읽습니다.
- 게다가 `PromptTemplateRegistry`는 `.st` 파일 내용을 `ConcurrentHashMap`에 **한 번 읽으면 프로세스 종료 전까지 캐시**해두고 다시 안 읽습니다(`computeIfAbsent`, invalidate 로직 없음).

즉 지금까지 제가 고친 RagService, ToolStepRunner, 세 차례의 프롬프트 수정 전부 로직상으로는 맞는데, **실행 중인 인스턴스가 그 코드/리소스를 전혀 안 쓰고** 예전 빌드 그대로 돌고 있어서 매번 첫 버그(RAG 거부/echo)와 똑같은 증상이 반복된 겁니다.

**필요한 조치**: `mvn clean package`로 dstone-ai-engine을 다시 빌드하고, 실제 떠 있는 인스턴스를 재기동(로컬 `java -jar`든, Jenkins 파이프라인을 통해 이미지 재빌드 후 kind Pod에 재배포하든)해야 지금까지의 수정이 실제로 테스트됩니다. 재배포 방식은 어느 쪽으로 하고 계신가요 — 로컬 `java -jar`로 직접 띄우시나요, 아니면 Jenkins/kind 파이프라인을 쓰시나요?
