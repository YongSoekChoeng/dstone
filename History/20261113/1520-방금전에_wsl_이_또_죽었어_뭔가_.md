## 답변

결론부터 말씀드리면 **직전 코드 수정과는 관계가 없습니다.** Windows 호스트의 가상 메모리(커밋)가 바닥나면서 Windows가 WSL VM을 강제로 끊은 것입니다.

## 근거

**1. WSL이 죽은 세 번 모두 직전에 Windows가 "가상 메모리 부족"을 기록했습니다** (이벤트 `Resource-Exhaustion-Detector #2004`)

| Windows 경고 | WSL 마지막 로그 | 메모리를 가장 많이 쓴 프로세스 |
|---|---|---|
| 11-12 15:52:08 | 11-12 15:50 | vmmemWSL 11.3GB, eclipse 3.2GB, oracle.exe 2.2GB |
| 11-13 14:59:19 | 11-13 15:00:31 | vmmemWSL 12.3GB, eclipse 2.8GB + 1.6GB |
| 11-13 15:16:22 | 11-13 15:16:02 | vmmemWSL 12.6GB, eclipse 2.8GB + 1.6GB |

두 시계 사이에 1분 안팎 차이가 나는 건 chrony가 시간을 맞추지 못한 상태였기 때문입니다.

**2. WSL 안에서는 이상이 없었습니다.**
- 커널 로그에 OOM, 패닉, hang 같은 흔적이 없습니다. 다음 부팅에서 `orphan inodes deleted / recovery complete`가 찍혔는데, 리눅스가 스스로 내려간 게 아니라 밖에서 전원이 끊기듯 멈췄다는 뜻입니다.
- 15:00 직전 sar 기록을 보면 리눅스 메모리 사용률은 40%, 가용 메모리는 6.6GB였습니다. 나머지 약 5GB는 페이지 캐시였습니다.
- 두 번째로 죽은 세션(15:04~15:16)은 Redis와 Jenkins만 띄운 상태로 12분 만에 끊겼습니다. 이 세션에서 dstone 앱을 띄웠는지는 로그만으로 확인할 수 없었습니다. 다만 사용자 프로세스가 몇 GB를 썼더라도 원인은 호스트 쪽 커밋 부족입니다.
- 직전 커밋(`7eba480c`)은 JS·CSS·SQL과 `JspLinker`에 필드 하나를 더한 정도입니다. 메모리 사용량에 영향을 줄 변경이 아닙니다.

**3. 메모리 수치가 맞지 않습니다.**
- 호스트 물리 RAM은 **15.2GB**인데 `.wslconfig`는 WSL에 **memory=12GB**를 주고 있습니다.
- 지금 vmmemWSL이 3.2GB밖에 안 쓰는데도 커밋 사용량은 이미 31.6GB / 40.5GB입니다. Eclipse 2개, DBeaver, Chrome, Obsidian, Oracle XE가 함께 떠 있기 때문입니다.
- 리눅스가 페이지 캐시까지 채워 vmmemWSL이 12GB 한도에 닿으면 커밋 한도를 넘고, 그 시점에 VM이 끊깁니다.

**4. 메모리 반납 설정이 적용되지 않았을 가능성이 높습니다.** (추정)
`.wslconfig`에 이렇게 적혀 있습니다.
```
autoMemoryReclaim=gradual   # 유휴 시 캐시 메모리를 ...
sparseVhd=true              # 디스크(vhdx)도 ...
```
`.wslconfig`의 INI 파서는 줄 끝 주석을 지원하지 않는 것으로 압니다. 그렇다면 값이 `gradual   # ...` 전체로 읽혀 무효가 되고, 캐시를 Windows에 돌려주지 않게 됩니다. 이렇게 보면 vmmemWSL이 12GB 가까이 차 있던 것도 설명됩니다. 다만 직접 확인하지는 못했습니다. `wsl.exe --version` 출력도 인코딩이 깨져 읽지 못했습니다.

## 권장 조치 (효과가 큰 순서)

1. **`.wslconfig` 수정**: 줄 끝 주석을 별도 줄로 옮기고 `memory=12GB`를 `8GB` 정도로 낮춥니다. `processors`와 `swap`은 그대로 둡니다.
2. 수정 후 PowerShell에서 `wsl --shutdown`을 실행하고 WSL을 다시 엽니다.
3. Windows 쪽에서 당장 쓰지 않는 Eclipse 한 개와 Oracle XE를 내려 두면 여유가 더 생깁니다.

`.wslconfig`는 `C:\Users\jysn007\`에 있어서, 파일 수정을 `/app/dstone` 안으로 한정하는 평소 규칙 밖입니다. 원하시면 제가 위 내용대로 고치겠습니다. 직접 고치실 거면 `wsl --shutdown` 전에 지금 하던 작업을 저장해 두세요.
