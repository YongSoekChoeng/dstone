## M6에서 만든 것

- **하이브리드 검색**: 뜻으로 찾기(벡터)와 이름으로 찾기를 순위로 합칩니다. M4에서 못 맞히던 두 질문("totalAmount 계산", "DB 커넥션을 얻는 코드")이 이제 1위로 나옵니다. 임베딩이 끝나기 전이거나 임베딩 서버가 내려가 있어도 이름으로는 찾힙니다.
- **영향도 분석**: `GET /api/revisions/{id}/impact`에 테이블·SQL·타입·메소드 중 하나를 주면 닿는 진입점, 화면, 메소드를 신뢰도와 함께 돌려줍니다. `anybiz_prd`의 `TBCN_CONTRACT` 전체 조회가 1초 안에 끝납니다(진입점 96, 화면 65).
- **일반 문서 올리기**: `/api/documents`로 PDF·Word·텍스트를 올리면 코드와 같은 검색으로 찾힙니다. Word 설계서를 올렸을 때 코드 청크 1만 5천 건이 대기 중이어도 45초 안에 검색됐습니다(임베딩 우선순위).
- **호출자 인증**: API 키 필터를 추가했고 기본값은 꺼짐입니다. 켜면 올린 문서가 호출자별로 나뉘며, 다른 호출자는 목록·검색·삭제 모두 안 되는 것을 확인했습니다.
- **ai-engine Tool**: `KnowledgeTool`(Tool 7개)과 `sample-knowledge-agent`를 추가했습니다. 실제 LLM 호출 두 번으로 Agent가 Tool을 골라 쓰고 `LOW` 신뢰도 결과를 "확실하지 않음"으로 밝히는 것까지 봤습니다.

## 계획에 없었지만 같이 고친 것

- **접근자 규칙**: `DBUtil.getConnection()`처럼 짧지만 일을 하는 `get…` 메소드가 접근자로 걸러져 문서가 아예 없었습니다. "같은 이름의 필드가 있을 때만 접근자"로 좁혔고, 메소드 문서가 `anybiz_prd` 기준 5,156 → 5,375건으로 늘었습니다.
- **`rerunFrom` 옵션**: 분석 시작 요청에 단계 이름을 주면 그 단계부터 다시 돌립니다. 위 규칙을 모든 프로젝트에 다시 적용하는 데 썼습니다.
- **스키마**: `rag_embedding.priority` 컬럼을 추가하고 로컬 DB에 스키마 SQL을 다시 적용했습니다.

## 확인 결과와 남은 한계

- `dstone-knowledge` 단위 테스트 79건이 모두 통과했습니다.

- **Pod 배포**: ai-engine의 `k8s/configmap.yaml`에는 Tool 설정이 없어서, kind에 올릴 때 `dstone.ai.tool.knowledge`와 `KNOWLEDGE_HOST`를 넣어야 합니다. 이번 확인은 kind가 내려가 있어 `bin/startApp.sh`로 띄운 로컬 프로세스에서 했습니다.
