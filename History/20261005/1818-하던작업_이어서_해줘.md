`dstone-boot` 왼쪽 메뉴와 AI 화면 메뉴의 "코드 분석(Knowledge)"으로 들어갑니다.

| 화면 | 할 수 있는 것 |
|---|---|
| 프로젝트 · 분석 | 프로젝트 등록·수정, 분석 시작(증분 분석, 특정 단계부터 다시), 진행 상황과 취소, 리비전 목록·삭제, 보관 정책 적용, 리비전 요약(품질 지표·관계 신뢰도·진입점·임베딩 진행 등) |
| 검색 · 문서 | 뜻+이름 검색, 일반 문서 올리기·목록·삭제 |
| 영향도 · 호출 관계 | 테이블·SQL·타입·메소드의 영향도, 메소드의 부르는 쪽·불리는 쪽 |
| 리비전 비교 | 두 리비전의 차이 요약과 종류별 목록 |

브라우저는 `dstone-knowledge`를 직접 부르지 않고 `dstone-boot`의 중계 API(`/knowledge/api/call.do`)를 거칩니다. 중계는 `/api/` 아래 경로와 GET/POST/DELETE만 허용합니다.

## 확인한 것과 못 한 것

- **동작은 확인했습니다.** `dstone-boot`를 로컬(7081)로 띄우고, 각 화면의 스크립트를 jsdom(가짜 브라우저)으로 실제 서버에 붙여 돌렸습니다. 네 화면 모두 오류 없이 목록·요약·검색 결과·영향도·비교가 그려졌습니다.
- **화면 모양은 보지 못했습니다.** 이 환경에 브라우저가 없어서 배치와 스타일은 직접 한 번 보셔야 합니다.
- **권한 구분이 없습니다.** 로그인한 사용자는 누구나 분석을 시작하고 리비전을 지울 수 있습니다(기존 AI 화면과 같은 수준).
- **kind 배포는 확인하지 못했습니다.** 클러스터가 내려가 있어 로컬 프로세스로만 봤습니다. `env-k8s.properties`와 `k8s/configmap.yaml`에는 주소 설정을 넣어 두었습니다.

## 화면 폭

AI 메뉴와 Knowledge 메뉴가 같이 쓰는 CSS 한 곳에서 최대 960px로 묶여 있었습니다. 이것을 화면의 96%(최대 1600px)로 넓혔고, 두 메뉴의 모든 화면에 적용됩니다.

## 활용법 설명

- **"사용 안내" 화면을 새로 만들었습니다** (Knowledge 메뉴 위쪽의 "사용 안내"). 담은 내용은 다음과 같습니다.
  - 이 메뉴로 무엇을 할 수 있는지: "알고 싶은 것 → 어느 화면" 표
  - 처음부터 따라 하기: 등록 → 분석 → 결과 확인 → 물어보기
  - 말뜻: 프로젝트, 리비전, 증분 분석, 진입점, 신뢰도, 임베딩, methodId
  - 화면별 쓰는 법과 결과 읽는 법
  - 잘 안 될 때: 증상별 대처 표
- **각 화면 위쪽에 "이렇게 씁니다"를 붙였습니다.** 순서 설명과 함께, 누르면 입력 칸이 채워지는 예시 단추가 있습니다(예: "테이블 TB_BOARD 를 고치면"). 예시는 이미 분석해 둔 작은 게시판 예제 `struts-app` 기준입니다.
- **프로젝트 등록에 "라이브러리 jar 의 위치" 칸을 추가했습니다.** 안내에서 "LOW가 많으면 jar 위치를 지정하라"고 설명하는데, 화면에 그 입력 칸이 없었기 때문입니다.

## 확인한 범위

- 여섯 화면이 모두 오류 없이 열리고, 예시 단추로 채운 값으로 검색 입력과 영향도 분석이 동작하는 것을 jsdom으로 확인했습니다.
- 넓어진 폭이 실제로 어떻게 보이는지는 이번에도 브라우저로 보지 못했습니다. CSS 값이 적용된 것까지만 확인했습니다.
