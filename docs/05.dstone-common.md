## 1. 개요

`dstone-common`은 dstone 멀티모듈 프로젝트의 핵심 공통 라이브러리입니다. `dstone-boot`/`dstone-batch`/`dstone-batchadmin`/`dstone-ai-engine` 네 모듈이 전부 공통으로 사용하는 유틸리티, 설정, 기반 클래스를 제공합니다.

- **Artifact ID:** `dstone-common`
- **Packaging:** JAR (라이브러리)
- **역할:** 공통 기반 라이브러리 (다른 모듈에 의존성으로 포함)

## 3. 패키지 구조

```
src/main/java/net/dstone/common/
├── annotation/     # NoAspectLog — AOP 로깅 대상에서 특정 메소드를 제외하기 위한 마커 애노테이션
├── biz/            # BaseController/BaseService/BaseDao/BaseVo — 4개 계층의 공통 베이스 클래스(5절)
├── config/         # 프레임워크 자체 설정: Config(진입점)·ConfigProperty(+ENC 복호화)·ConfigAspect(로깅 AOP 뼈대)
├── consts/         # ErrCd 등 상수/Enum 정의
├── core/           # BaseObject 등 전 계층이 상속하는 최상위 추상 클래스
├── exception/      # BizException/SecException 공통 예외 클래스
│   └── resolver/   # DsExceptionResolver — 예외를 ErrCd 응답 헤더/에러 뷰로 변환
├── messaging/      # SAGA/Outbox 패턴 구현 - 10.dstone-saga.md 참고
│   ├── outbox/     # OutboxAppender(Impl)/OutboxStore/OutboxRelay
│   └── saga/       # SagaOrchestrator/SagaStore/SagaStepHandler
├── queue/          # QueueHandler/QueueItem — dstone-boot 소스분석기·dstone-batch 샘플잡이 사용하는 경량 큐 추상화
├── socket/         # Client/Server — TCP 소켓 통신 유틸(레거시, 2026-09 기준 다른 모듈에서 사용처 없음)
├── task/           # TaskHandler/TaskItem — dstone-boot 소스분석기가 쓰는 비동기 작업 단위 추상화
├── utils/          # 범용 유틸리티 클래스(4절)
└── websocket/      # WebSocket 핸들러/컨트롤러 — dstone-boot의 ConfigWebSocket이 연결
```

> ℹ️ `config/`는 이름과 달리 **Redis/RabbitMQ/WebSocket 자체를 설정하지 않는다** — 그건 각 모듈(`dstone-boot`/`dstone-batch`/`dstone-batchadmin`/`dstone-ai-engine`)이 자기 `common/config/Config*.java`에서 직접 구성한다. `dstone-common`의 `config/`는 그 모든 모듈이 공유하는 두 가지, 즉 **① `ENC(...)` 복호화**(`ConfigProperty`)와 **② 로깅 AOP의 공통 뼈대**(`ConfigAspect`)만 담당한다.

> 🆕 **2026-09-14 — `ConfigProperty`에 리스트/맵 프로퍼티 조회 추가.** `application.yml`의 YAML 시퀀스(리스트-오브-오브젝트)를 스칼라 조회(`getProperty`)로는 읽을 수 없어서, 지금까지는 그런 값이 필요한 기능마다(`dstone-ai-engine`의 옛 `ApiKeyProperties`/`RateLimitProperties`처럼) 각자 `Binder`를 직접 호출하는 전용 `*Properties` 클래스를 새로 만들어야 했다. `getListProperty(String)`가 내부적으로 `Binder`를 쓰도록 바뀌면서(예전 구현은 `env.getProperty(key, List.class)`로 관대한(relaxed) 리스트 바인딩이 되지 않았다), 이제 그런 값도 `configProperty.getListProperty("some.yaml.list")` 한 줄로 바로 `List`(원소는 대개 `Map`)를 받을 수 있다. 같은 방식의 `getMapProperty(String)`(YAML 맵 → `Map<String,Object>`)도 함께 추가됐다. `dstone-ai-engine`의 `common.filter.ApiKeyAuthFilter`/`RateLimitFilter`가 이 방식으로 단순화된 첫 사례다(전용 `*Properties` 클래스 없이 필터 안에서 바로 `getListProperty()` 호출) — 자세한 배경은 [09.dstone-ai-engine.md 8절](09.dstone-ai-engine.md#8-phase-4--governance--observability-api-key-인증-rate-limit-pii-guardrail-사용량-로깅) 참고. 다만 특정 레코드 타입(예: `List<UsagePricing>`)으로 바로 바인딩해야 하는 경우는 여전히 `Binder`를 직접 쓴다(`UsageProperties`가 그 예).
>
> ⚠️ **2026-09-14 실동작 검증 중 발견된 버그 수정 — 원소 타입은 `Object`가 아니라 `Map`이어야 한다.** 처음 커밋된 구현은 `Bindable.listOf(Object.class)`를 썼는데, `dstone-ai-engine`의 `governance.auth.keys`(Phase 5 실동작 검증, 캐패빌리티/Tool 화이트리스트 테스트 중 실제로 API를 호출해보다가 발견)에서 항상 `UnboundConfigurationPropertiesException`(`elements were left unbound`)으로 기동 자체가 실패하는 게 확인됐다 — Spring의 `Binder`가 리스트 원소를 `Object`로 바인딩할 때는 그 타입을 평범한 JavaBean처럼 취급해서 프로퍼티 setter를 찾으려 하는데, `Object`에는 당연히 `caller`/`key` 같은 setter가 없어서 실패한다. 리스트 원소 타입을 `Bindable.listOf(Map.class)`로 바꾸면 `Binder`가 `Map`을 "잘 알려진 집합 타입"으로 인식해 각 키를 그대로 채워준다 — 지금 코드는 이 수정이 반영된 상태다. **교훈**: 이런 종류의 `Binder` 바인딩 버그는 컴파일도 되고 기동도 정상인 경우가 있고(예: 리스트가 아예 비어있거나 그 설정 키를 안 쓰는 배포), 실제로 값이 있는 YAML 시퀀스를 로딩하는 순간에만 터진다 — 코드 리뷰나 유닛 테스트만으로는 놓치기 쉽고, 실제 설정값을 채운 채로 기동해보는 실동작 검증이 아니면 드러나지 않는다.

| 메소드 | 반환 타입 | 용도 |
|---|---|---|
| `getProperty(String)` | `String` | 스칼라 값 1건 조회(가장 흔한 경우) |
| `getListProperty(String)` | `List`(원소는 보통 `Map`) | YAML 시퀀스(리스트-오브-오브젝트) 조회 — 원소를 `Bindable.listOf(Map.class)`로 바인딩(`Object.class`는 중첩 맵을 못 받아 `UnboundConfigurationPropertiesException`으로 실패함, 위 경고 박스 참고) |
| `getMapProperty(String)` | `Map<String, Object>` | YAML 맵 조회 |
| `getEnv()` | `Environment` | 위 3개로 부족한 경우(예: 특정 레코드 타입으로 직접 바인딩) 원본 `Environment`를 꺼내 `Binder.get(getEnv())...`처럼 직접 쓸 때 |

## 4. 주요 유틸리티 (`net.dstone.common.utils`)

| 클래스 | 설명 |

| `LogUtil` | 구조화된 로깅 (Log4j2 기반) |

| `EncUtil` | 암복호화 (Jasypt PBEWithSHA256And128BitAES-CBC-BC, BouncyCastle) - `ENC(...)` 값 복호화 및 신규 값 생성(8절 참고) |

## 5. 공통 베이스 클래스 (`net.dstone.common.biz`)

`dstone-boot`/`dstone-batchadmin`을 비롯한 웹 계층 모듈은 자기 Controller/Service/Dao/Vo를 아래 4개 추상 클래스 중 하나를 상속해서 만든다(전 리포지토리 기준 31곳에서 상속). 그래야 로깅·세션·REST 호출·에러코드 응답 같은 반복 작업을 매번 새로 짜지 않아도 된다.

```mermaid
classDiagram
    class BaseObject {
      <<net.dstone.common.core>>
      +info(msg)
      +warn(msg)
      +error(msg)
    }
    BaseObject <|-- BaseController
    BaseObject <|-- BaseService
    BaseObject <|-- BaseDao
    class BaseController {
      <<@Controller>>
      +getSession()
      +logInput()/logOutput()
      +setErrCd(ErrCd)
      +proxy() "/proxy.do"
      +view1~4() "/views/{..}"
    }
    class BaseService {
      <<@Service>>
      +getRestTemplate()
      +getWebClient()
    }
    class BaseDao {
      <<@Repository>>
      "MyBatis SqlSessionTemplate 접근 지점"
    }
    class BaseVo {
      <<Serializable>>
      +PAGE_SIZE/PAGE_NUM/INT_FROM/INT_TO
    }
```

| 클래스 | 계층 | 핵심 기능 |
|---|---|---|
| `BaseController` | Web (`@Controller`) | `getSession()` 세션 헬퍼, `logInput()`/`logOutput()` 요청·응답 JSON 로깅, `setErrCd()`(ErrCd를 `errCd`/`errMsg` 응답 헤더로 세팅 — AJAX면 URL 인코딩, 아니면 Base64), `RestTemplate` 기반 범용 프록시(`/proxy.do`), 경로변수 뷰 라우팅(`/views/{a}/{b}/...`), `favicon.ico` 무동작 처리(Boot 3+의 `NoResourceFoundException` 로그 방지) |
| `BaseService` | Service (`@Service`) | 외부 연동용 `RestTemplate`(`getRestTemplate()`)과 `WebClient`(`getWebClient()`, SSE 등 스트리밍용, 기본 타임아웃 60초·오버로드로 연장 가능) 제공 |
| `BaseDao` | Repository (`@Repository`) | MyBatis `SqlSessionTemplate` 접근을 위한 공통 지점(현재는 표식 역할, 구체 쿼리 메소드는 각 모듈의 `*Dao` 구현체에 있음) |
| `BaseVo` | VO/DTO | 화면 그리드 페이징 공용 필드(`PAGE_SIZE`/`PAGE_NUM`/`INT_FROM`/`INT_TO`) |

> ⚠️ `BaseVo`는 `@XmlRootElement(name="MemberVo")`로 고정돼 있다 — 모든 하위 VO가 상속받아도 XML 루트 엘리먼트 이름은 항상 `MemberVo`로 나온다는 뜻이다. JSON 응답(`ConvertUtil`/Jackson 경유)에는 영향이 없지만, XML 바인딩을 실제로 쓰는 화면이 있다면 그 결과가 의도와 다를 수 있으니 유의할 것(이 문서 갱신 시점 기준으로 코드 동작을 있는 그대로 기록한 것이며, 별도 수정 지시가 없어 손대지 않았다).

`BaseController`가 쓰는 에러코드 체계(`net.dstone.common.consts.ErrCd`)는 `'E'(에러)/'W'(경고)/'I'(정보) + 'XXX'(업무명) + '0000'(시퀀스)` 컨벤션의 Enum이며(예: `SYS_ERR`="ESYS0001"), 예외 발생 시 `net.dstone.common.exception.resolver.DsExceptionResolver`(`SimpleMappingExceptionResolver` 확장)가 `BizException`/`SecException`이면 그 예외가 든 `ErrCd`를, 그 외는 `ErrCd.SYS_ERR`를 자동으로 응답 헤더에 실어준다.

## 6. 공통 설정 패턴

모든 모듈의 `conf/application.yml`에서 공통으로 참조하는 설정 구조:

```yaml
# Redis (Lettuce 클라이언트)
spring.data.redis:
  host: ${REDIS_HOST}
  port: ${REDIS_PORT}
  client-type: lettuce
  lettuce.pool:
    max-active: 5
    max-idle: 5
    min-idle: 2

# RabbitMQ (Fanout + Direct Exchange)
spring.rabbitmq:
  host: ${RABBITMQ_HOST}
  port: ${RABBITMQ_PORT}

# 데이터소스 (HikariCP + log4jdbc)
spring.datasource.<name>.hikari:
  driver-class-name: net.sf.log4jdbc.sql.jdbcapi.DriverSpy
  jdbc-url: jdbc:log4jdbc:mysql://${DB_HOST}:${DB_PORT}/<database>
  username: ENC(...)   # Jasypt 암호화
  password: ENC(...)
```

## 8. 보안 아키텍처

- **Jasypt**: `application.yml` 내 민감 정보(DB 비밀번호 등)를 `ENC(...)` 형식으로 암호화 저장. 복호화 키는 `EncUtil.java`에 하드코딩되어 있으며(`env.properties`가 아님), 복호화 자체는 `ConfigProperty`의 static nested `EncPropertyEnvironmentPostProcessor`(`META-INF/spring.factories`로 등록)가 PropertySource 레벨에서 처리한다 — jasypt-spring-boot-starter는 Boot 4를 지원하지 않아 제거했고, 모듈별 `ConfigEnc` 빈도 더 이상 없다
- **BouncyCastle**: JDK 17+ 환경에서의 중첩 JAR 보안 문제 해결 및 암호화 알고리즘 확장
- **JJWT 0.11.5**: JWT 토큰 생성 및 검증

## 9. 애플리케이션 기동 순서

`setSysProperties()`는 `dstone-common`이 공유 구현을 제공하는 게 아니라, **모듈마다(`DstoneBootApplication`/`DstoneBatchApplication`/`DstoneBatchAdminApplication`/`DstoneAiEngineApplication`) 각자 자기 `main()` 클래스 안에 똑같은 이름·역할로 구현해둔 공통 컨벤션**이다. 4개 모듈 모두 이 순서를 따른다:

1. `setSysProperties()` 호출 → `conf/env.properties`(또는 프로파일별 `env-<profile>.properties`) 내용을 System Properties로 등록
2. `APP_CONF_DIR` 경로의 `application.yml` 로드
3. `log4j2.xml` 로깅 설정 로드
4. Spring Boot 자동 설정 활성화

> 과거 버전의 흔적인 `net.dstone.common.utils.InitServlet`(`PropUtil` 기반 서블릿 초기화)이 `dstone-common`에 남아 있지만, 현재 4개 모듈 어디에서도 참조하지 않는 미사용 레거시 클래스다 — 실제 기동 초기화는 위 `setSysProperties()` 컨벤션으로 완전히 대체되었다.

## 10. 빌드

```bash
# 공통 라이브러리 빌드 (다른 모듈 빌드 전 선행 필요)
cd dstone-common
mvn clean install
```

빌드 시 `conf/` 디렉토리의 `.properties` 파일이 `target/classes`로 복사됩니다.

> 전체 모듈 빌드 명령, 배포 방식, CI/CD 파이프라인 종합 정리는 [03.build.md](03.build.md) 참고.
